# Repository settings

GitHub settings live outside git, so we keep them **as code** instead:

- `scripts/setup-github.sh` applies them (labels, milestones, autolinks, repo settings, ruleset, security).
- `scripts/github/ruleset-main.json` defines the ruleset protecting `main`.
- `scripts/check-github.sh` checks the live settings against them and fails on any drift. Run without a repo admin's token, it shows each setting it can't read as 🔒 instead.

**To change a setting:** edit the script or JSON in a PR, then after merge the tech lead runs `./scripts/setup-github.sh` followed by `./scripts/check-github.sh`. Don't change settings by hand in the GitHub UI. If you have to (e.g. in an emergency), follow up with a PR so the scripts match again.

## What's set and why

| Setting                                  | Value                                                                                                                           | Why                                                                                                                                                                                |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Merge methods                            | Squash only                                                                                                                     | One commit on `main` per PR; linear history                                                                                                                                        |
| Squash commit message                    | PR title + commit messages                                                                                                      | Keeps each PR's `plan(…): approved by @…` line in `main`'s history                                                                                                                 |
| Delete branch on merge                   | On                                                                                                                              | No stale branches                                                                                                                                                                  |
| Suggest updating PR branches, auto-merge | On                                                                                                                              | Branches stay current; nothing auto-merges ([Dependencies](dependencies.md))                                                                                                       |
| Wiki, Projects, Discussions              | Off                                                                                                                             | Fewer places for the PO to look. Work lives in Issues                                                                                                                              |
| Issue and PR creation                    | Collaborators only                                                                                                              | The repo is public; outsiders can read and fork but not open issues or PRs                                                                                                         |
| Interaction limit                        | Collaborators only, six months                                                                                                  | Covers comments; GitHub drops it after six months. `setup-github.sh` records the expiry; `backlog-interaction-limit.yml` opens a Chore and `check-github.sh` fails 30 days before  |
| Ruleset _Protect main_                   | No deletion, no force push, linear history, PR required                                                                         | `main` only changes through a PR a code owner has approved                                                                                                                         |
| Required approvals                       | 1, stale approvals dismissed, conversations resolved, an extra approval when a commit's author isn't its pusher                 | One approval from the PO or the tech lead is enough for now                                                                                                                        |
| Last-push approval, up-to-date branches  | Required                                                                                                                        | A push after approval needs a fresh approval; checks run on what will merge                                                                                                        |
| Rulesets _Protect po-preview_, _Tags_    | No deleting `po-preview`; no creating, changing or deleting tags                                                                | `po-preview` (the PO's link) can't be deleted; release tags only move by the tech lead                                                                                             |
| Code-owner review                        | Required; `.github/CODEOWNERS` covers every path                                                                                | Every PR needs the PO's or the tech lead's approval; the lines after the catch-all need the tech lead's and are the hand-back paths. The tech lead's bypass still works            |
| Bypass                                   | Repository admin, **via PR only**                                                                                               | The tech lead can merge their own PRs (you can't approve your own PR). Every bypass is logged                                                                                      |
| Required status checks                   | The contexts in `scripts/github/ruleset-main.json`, each from the app its `integration_id` names (GitHub Actions, Codecov)      | Nothing merges with a red check, and only the named app's report counts                                                                                                            |
| Dependabot alerts and security fixes     | On                                                                                                                              | Vulnerable dependencies are flagged and fixed by PR                                                                                                                                |
| Secret scanning, push protection         | On                                                                                                                              | A secret is flagged, and blocked at push                                                                                                                                           |
| Private vulnerability reporting          | On                                                                                                                              | Outsiders report privately ([SECURITY.md](../SECURITY.md))                                                                                                                         |
| Actions token                            | Read-only; can't approve PRs                                                                                                    | Least privilege; an agent's workflow can't approve its own PR                                                                                                                      |
| Actions pinned to a full SHA             | Required                                                                                                                        | A moved tag can't change what runs                                                                                                                                                 |
| Allowed actions                          | GitHub's, this repo's, `claude-code-action`, `codecov-action`, `setup-bun`                                                      | A new third-party action, or one an allowed action calls (`setup-bun` is `claude-code-action`'s), needs a PR to this list                                                          |
| Secrets and variables                    | The names in [_Secrets and variables_](#secrets-and-variables)                                                                  | Each job that acts as the bot mints a one-hour token from the App's key with only the permissions it needs (`actions/create-github-app-token`). No personal access token is stored |
| Labels                                   | The list in `scripts/github/labels.sh`, and no other                                                                            | `setup-github.sh` creates them and deletes the retired ones; `check-github.sh` compares. The tech lead adds `fix-review` to a PR to start `claude-fix-review.yml`                  |
| Autolinks                                | One per requirement ID prefix, from `docs/requirements.md`; the URL names `main` and ends in its `#map-03`-style anchors (#510) | A bare `MAP-03` in an issue, PR or commit links to its row                                                                                                                         |
| Code scanning                            | CodeQL default setup                                                                                                            | Free on a public repo; flags vulnerable code in PRs                                                                                                                                |
| Fork PR workflow runs                    | Need approval, for all outside contributors                                                                                     | An outsider's PR runs nothing until the team approves it                                                                                                                           |

## Vercel

Vercel has no settings-as-code here: the tech lead sets these by hand in the Vercel dashboard, and nothing checks for drift. Update this table in the same PR as any change.

| Setting                      | Value                                                                                                                                                                              | Why                                                                                                                                                                                                               |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Project                      | `kinscape`, Hobby plan, Git repo `henetiriki/kinscape`                                                                                                                             | Builds previews and production; the Deploy rule below says which pushes skip                                                                                                                                      |
| Production branch            | `main`                                                                                                                                                                             | Production only changes through a merged PR                                                                                                                                                                       |
| Framework, Node              | Next.js; Node 24.x (from `package.json` `engines`)                                                                                                                                 | Matches local development                                                                                                                                                                                         |
| System Environment Variables | "Enable access to System Environment Variables" is on (Project Settings, Environment Variables)                                                                                    | Vercel then sets `VERCEL` and `VERCEL_ENV` at build and runtime ([docs](https://vercel.com/docs/environment-variables/system-environment-variables)). Off, the `KINSCAPE_MEMORY_ADAPTERS` guard below never fires |
| Vercel Authentication        | Standard Protection: previews need a Vercel sign-in, production is public                                                                                                          | Previews stay private; production is empty until sign-in (NFR-03) arrives in M2                                                                                                                                   |
| Ignored Build Step           | Automatic (the default) in the dashboard; `vercel.json` runs `scripts/vercel-ignore.mts`                                                                                           | The file is the only rule                                                                                                                                                                                         |
| Deploy rule                  | A push skips its deployment only when every changed file is on the invisible list in `scripts/vercel-ignore.mts`. `po-preview` always deploys. If GitHub can't be read, it deploys | Plan, docs, test and CI changes nobody can see don't deploy, and a docs-only merge doesn't redeploy production                                                                                                    |
| `KINSCAPE_REPO_SLUG`         | The repo as `owner/name`; Production and Preview. Set by hand: the script has no Vercel login                                                                                      | The script asks the GitHub API about this repo. Unset, every push deploys                                                                                                                                         |
| `KINSCAPE_GIT_READ_TOKEN`    | Fine-grained token for `henetiriki/kinscape` only, Contents read-only; Sensitive, Production and Preview; expires after 90 days; the owner rotates it                              | The script reads the changed files from the GitHub API, as Vercel's clone has no remote. Once it expires every push deploys until a new one is set                                                                |

Database variables (NFR-03, NFR-09). All are Sensitive; the values are in Vercel only, never in git. Preview points at `kinscape-preview`, Production at `kinscape-production`. Before running `db:migrate` or `account:add` with production variables, diff the script against the version you last ran.

| Variable                            | Value                                                                                                                                        | Why                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `KINSCAPE_DATABASE_URL`             | The project's transaction-pooler connection string (port 6543) ending `?sslmode=verify-full`; Production and Preview, each its own project's | The app's database connection (M2.3 `env.ts`). The transaction pooler supports no named prepared statements, so the client turns them off. A Production value in Preview would put synthetic data beside the real Tree. The server verifies the certificate against `server/db/root-ca.crt` whatever the URL says, and refuses to start on any other TLS parameter (B608) |
| `KINSCAPE_SUPABASE_URL`             | The project's API URL; Production and Preview, each its own project's                                                                        | Sign-in (M2.5.1)                                                                                                                                                                                                                                                                                                                                                          |
| `KINSCAPE_SUPABASE_PUBLISHABLE_KEY` | The project's publishable key; Production and Preview, each its own project's                                                                | Signs users in but can't manage them. The secret key is not used and is set nowhere                                                                                                                                                                                                                                                                                       |
| `KINSCAPE_DATABASE_DIRECT_URL`      | The project's session-pooler connection string (port 5432) ending `?sslmode=verify-full`; in no Vercel environment                           | Only for `npm run db:migrate` and `account:add`, which the tech lead runs locally from a git-ignored `.env.local`. Migrations need a session, which the transaction pooler doesn't keep. Same TLS rules as `KINSCAPE_DATABASE_URL`                                                                                                                                        |
| `KINSCAPE_MEMORY_ADAPTERS`          | `1` in local dev and e2e only; never set in Vercel                                                                                           | Test-only: swaps in the memory session, sessions, store and sign-in throttle, needing no database or Supabase variable. The server refuses to start if it is set with `VERCEL` or `VERCEL_ENV` (see _System Environment Variables_ above)                                                                                                                                 |

## Supabase

Supabase has no settings-as-code here: the tech lead sets these by hand in the Supabase dashboard, and nothing checks for drift.

| Setting                             | Value                                                                                                                                        | Why                                                                                                                                                                                                        |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Projects                            | `kinscape-preview` (Vercel Preview) and `kinscape-production` (Vercel Production); free tier                                                 | Preview deployments never touch the real Tree                                                                                                                                                              |
| Region                              | `eu-west-1` in both projects                                                                                                                 | Spec #527 D1: Cape Town if offered, else EU                                                                                                                                                                |
| Sign-ups                            | Off in both projects                                                                                                                         | v1 has no sign-up ([requirements](requirements.md) _Users_, NFR-03)                                                                                                                                        |
| Email provider                      | On in both projects (Authentication → Sign In / Providers → Email)                                                                           | Sign-in is Supabase Auth's password grant; with it off Auth answers 422 and every sign-in shows "can't sign you in right now"                                                                              |
| Data API                            | Off ("Only connection string") in both projects; Supabase Auth stays on                                                                      | The app reaches Postgres directly and never uses `supabase-js` for data, so nothing needs it                                                                                                               |
| Automatic RLS on new tables         | On in both projects                                                                                                                          | With no policies it denies the anon and authenticated roles. The server connects as the table owner, which bypasses RLS, so app queries are unaffected. A second layer if the Data API is ever switched on |
| Disabling a user                    | Also delete their `session` rows                                                                                                             | Supabase Auth doesn't know the app's sessions; they last up to 90 days                                                                                                                                     |
| Clearing a sign-in lock             | `delete from sign_in_failure where email_key = encode(sha256(convert_to('<email>', 'UTF8')), 'hex')`, with the email trimmed and lower-cased | Five failures lock an email for 15 minutes; rows hold only the hash (NFR-03)                                                                                                                               |
| Pausing                             | An idle free project pauses; the tech lead resumes it in the dashboard                                                                       | Free tier limit                                                                                                                                                                                            |
| Enforce SSL on incoming connections | On in both projects (Settings → Database → SSL)                                                                                              | Only TLS connections reach Postgres and the poolers. The server pins `server/db/root-ca.crt` (Supabase Root 2021 CA, expires 26 April 2031); replace the file in a PR before then (B608)                   |

## Secrets and variables

The names are listed in `scripts/check-github.sh` (`expected_secrets`, `expected_variables`), which fails on a missing or extra one. Names only; no value is read.

| Names                                                                | Set by                 | Read by                                                           |
| -------------------------------------------------------------------- | ---------------------- | ----------------------------------------------------------------- |
| Variables `KINSCAPE_BOT_LOGIN`, `KINSCAPE_BOT_ID`                    | `setup-github.sh`      | Workflows and the `run-claude` action, for the bot's login and id |
| Variable `KINSCAPE_TEAM_LOGINS`                                      | `setup-github.sh`      | The `run-claude` action: whose comments the agents read           |
| Variable `KINSCAPE_INTERACTION_LIMIT_EXPIRES`                        | `setup-github.sh`      | `backlog-interaction-limit.yml`, to open a Chore 30 days before   |
| Variable `KINSCAPE_APP_CLIENT_ID`, secret `KINSCAPE_APP_PRIVATE_KEY` | The tech lead, by hand | Each job that mints the App's token                               |
| Secret `CLAUDE_CODE_OAUTH_TOKEN`                                     | The tech lead, by hand | The Claude workflows, for the model                               |

Codecov needs no secret: `ci.yml`'s `coverage` job uploads with its own OIDC token.
