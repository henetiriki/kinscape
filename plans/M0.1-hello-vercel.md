# Plan: M0.1: Hello Vercel

- **Spec:** #8
- **Requirement IDs:** NFR-03 (part: nothing indexed by search engines)
- **Status:** approved

## Approach

Build a minimal Next.js app (App Router, TypeScript, npm) by hand, so no `create-next-app` demo files come in. One client component creates a MapLibre GL JS map whose inline style has only a background layer: no sources, tiles or borders. The map fills the window, is centred on South Africa (25°E, 29°S, zoom 4.5), and has zoom buttons and a scale bar so the PO can see zoom working. The root layout's metadata puts a `noindex` tag on every page, and `app/robots.ts` disallows all crawlers. Node is pinned to 24 LTS. Vercel's Git integration builds every PR and every merge to `main`, so there's no `vercel.json`.

## Order of work

1. Commit this plan on `spec/M0.1-hello-vercel`, cut from `origin/main`.
2. Scaffold the app and install the dependencies. Run `npm run build`.
3. Add the map, robots metadata and `robots.ts`. Check them locally.
4. Update `AGENTS.md` and `docs/repo-settings.md`.
5. Open the PR (Closes #8). Confirm Vercel builds a preview, then set #8 to `status: ready-for-po`.

**Tech lead, before step 5:** create the Vercel project from `henetiriki/kinscape` and turn on Vercel Authentication (Standard Protection).

## Risks

- **Vercel Hobby author check.** The `Co-Authored-By: Claude` line may block deploys. The first preview shows whether it does. If it does, a chore PR drops the line.
- **MapLibre on the server.** It touches `window`, so the map is created in `useEffect` inside a `'use client'` component. The build proves this works.
