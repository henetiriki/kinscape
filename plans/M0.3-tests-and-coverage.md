# Plan: M0.3: Tests and coverage

- **Spec:** #15
- **Requirement IDs:** none (M0 Foundations: CI with tests)
- **Status:** approved

## Approach

Vitest runs unit tests in jsdom with the v8 coverage provider, thresholds at 100% for all four metrics over `{app,components,scripts}/**/*.{ts,tsx,js,mjs}`, excluding config and test files and `.claude/`. Unit tests sit in a `__tests__` folder next to the source they test, as `*.test.ts(x)`. Vite's own transform handles TSX (tsconfig has `react-jsx`) and a `resolve.alias` maps `@/`, so no Vite plugins are needed. One Playwright test in `e2e/` builds and starts the app, then checks the map canvas. CI gains `test` and `e2e` jobs. The `test` job uploads `lcov` to Codecov even after a failed run, so the patch status still reports. `codecov.yml` sets project and patch targets to 100%. Nothing becomes required until M0.5.

Exact dev dependencies, pinned at install: `vitest`, `@vitest/coverage-v8`, `jsdom`, `@testing-library/react`, `@playwright/test`.

## Risks

- **WebGL in headless Chromium:** recent Chromium no longer falls back to SwiftShader on its own. `--use-angle=swiftshader --enable-unsafe-swiftshader` fixes this, and the CI run proves it.
- **`new URL(…, import.meta.url)` under Vitest:** `setWorkerUrl` is mocked, so the test only checks the URL string. If Vite rewrites it, the test asserts on the file name.
- **Codecov outage:** upload errors don't fail the `test` job. Once M0.5 requires Codecov's statuses, a missing status still blocks merges (flagged in the Spec).
