# Plan: M0.5: Word count and required checks

- **Spec:** #17
- **Requirement IDs:** none (M0 Foundations, CI)
- **Status:** approved

## Approach

`scripts/word-count.mts` is the only place budgets are defined. Each budget is a path pattern and a limit: `CLAUDE.md` 150, `AGENTS.md` 800, `docs/how-we-work.md` 800, `plans/*.md` 600, and `.claude/skills/**/*.md` 600 except `NOTICE.md`. A word is any whitespace-separated token that contains a letter or digit, so table pipes and `---` rows don't count. Front matter and code blocks do count. With no arguments the script finds and checks every budgeted file. Given paths, it checks only those, and paths with no budget pass. Each file over budget prints `<path>: <n> words, budget <b>`. Like the boundary validator, it uses only Node built-ins, so CI needs no `npm ci`.

`--hook` mode reads Claude's `PostToolUse` JSON from stdin, takes `tool_input.file_path` relative to the repo, and exits 2 if that file is over budget (CI exits 1). The `ruleset-main.json` file adds a `required_status_checks` rule listing `lint`, `format`, `test`, `e2e`, `boundaries`, `words`, `codecov/project` and `codecov/patch`. It doesn't require branches to be up to date.

## Risks

- **`.claude/settings.json` is write-protected** in Claude's sandbox, so the tech lead approves that edit when prompted.
- **Check names must match exactly.** They come from this PR's check list, not from guesses.
- **If the Codecov upload fails,** its statuses never post and the PR blocks. Re-running the job clears it.
- **`fs.globSync`** may warn. If it does, use `readdirSync` with `recursive`.
