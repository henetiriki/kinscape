# Plan: M0.6: Lint hooks

- **Spec:** #19
- **Requirement IDs:** none (M0 Foundations: tooling)
- **Status:** approved

## Approach

Husky 9.1.7 runs lint-staged 17.6.0 on `git commit`; a Claude Code PostToolUse hook stages the edited file and runs lint-staged. Both reuse the M0.2 ESLint and Prettier configs unchanged.

- **lint-staged** (`.lintstagedrc.json`): `*.{js,jsx,mjs,cjs,ts,tsx,json}` → `eslint --fix --max-warnings 0 --no-warn-ignored`; `*` → `prettier --write --ignore-unknown`. The pre-commit hook runs `lint-staged --concurrent false` so the two never write one file at once. `--no-warn-ignored` stops ignored files tripping `--max-warnings 0`.
- **Edit hook:** the tech lead's command, below, in place of a wrapper script and `fix:file`. It reuses `.lintstagedrc.json`.
- **Install:** `"prepare": "husky"`. Husky 9 prints a notice and exits 0 when `.git` is missing (Vercel), and CI has devDependencies, so neither fails.
- **Unstaged changes:** lint-staged's default stash keeps unstaged hunks of a partially staged file; proven below.

Hook entry for the tech lead to add to `.claude/settings.json`:

```json
"hooks": {
  "PostToolUse": [
    {
      "hooks": [
        {
          "command": "git add -- $CLAUDE_FILE_PATHS 2>/dev/null; yarn lint-staged",
          "statusMessage": "Linting the edited file",
          "timeout": 60,
          "type": "command"
        }
      ],
      "matcher": "Edit|Write"
    }
  ]
}
```

## Risks

- **Unverified edit-hook command:** `$CLAUDE_FILE_PATHS` may be empty (the path normally arrives as JSON on stdin), the repo uses npm not `yarn`, lint-staged exits 1 not 2 so errors may not reach Claude, and `git add` stages every edit. The live check decides.
- **Hook not reloaded mid-session:** restart the session and repeat.
