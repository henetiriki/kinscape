# Plan: M0.8: Skip Claude review on some PRs

- **Spec:** #39
- **Requirement IDs:** none (engineering-only; CI has no requirement ID)
- **Status:** approved

## Approach

Two changes to `.github/workflows/claude-code-review.yml`:

- **Docs-only PRs:** add `paths-ignore: ['docs/**', 'plans/**']` to the `pull_request` trigger. GitHub skips the workflow only when _every_ changed file matches, so a PR that also touches `AGENTS.md`, `.github/**` or any code still runs. Remove the commented-out `paths:` example.
- **Drafts:** extend the job's `if` to `github.actor != 'dependabot[bot]' && !github.event.pull_request.draft`. `ready_for_review` is already in `types`, so marking a draft ready runs the review. Keep the Dependabot comment; remove the commented-out author-filter example.

`docs/how-we-work.md` › _Building a Spec_ gains one line: "Claude reviews each pull request automatically, except drafts, Dependabot PRs and PRs that change only `docs/` or `plans/`."

## Alternatives considered

- A job-level `if` that lists changed files (e.g. `dorny/paths-filter`): adds a dependency and a job run for nothing. `paths-ignore` is native and doesn't start a run at all.

2. Edit the workflow and doc; run lint, format check, tests, boundary validator and `npm run words`.

4. Run the throwaway PRs below against the branch; record results in the PR; close and delete them.

## Risks

- **Required check:** a path-filtered workflow leaves a required check pending. The review isn't required (M0.5); noted in the Spec.
- **Workflow changes take effect from the PR's head** for `pull_request` events, so throwaway PRs based on the branch exercise the new config.
- **Over 300 changed files:** GitHub ignores path filters and runs the workflow. Harmless.
