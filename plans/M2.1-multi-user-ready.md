# Plan: M2.1: Multi-user ready requirements

- **Spec:** #48 (Intent #13)
- **Requirement IDs:** NFR-03, NFR-04, NFR-09 (new), PPL-01, PPL-02, PIN-01, PIN-02, PIN-07, BND-06
- **Status:** approved

## Approach

Intent #13 asks that M2's storage and sign-in not lock Kinscape to one user. This Spec only edits `docs/requirements.md`, so M2 is designed against an Account and a Tree from the start. No code, no screens. The wording follows the Spec's _Behaviour and UX_ section, using Key concepts terms exactly.

## Files that change

| File                             | New / changed | What                   |
| -------------------------------- | ------------- | ---------------------- |
| `docs/requirements.md`           | Changed       | The edits listed below |
| `plans/M2.1-multi-user-ready.md` | New           | This plan              |

Edits to `docs/requirements.md`. First-person references become "the user" throughout, not "the product owner" (tech lead's choice at plan review, departing from the Spec's wording).

1. **Purpose:** "my ancestors" → "the user's ancestors".
2. **Users:** "One in v1. No sign-up or sharing, but the data must stay private and be backed up, and adding users later must not need a rebuild (NFR-09)."
3. **Key concepts:** add _Account_ (someone who signs in to Kinscape; never a Person) and _Tree_ (the people, relationships, pins, sources and places that one or more Accounts work on).
4. **Map checks:** "when I click" → "when the user clicks" (two checks).
5. **Pins intro:** "how I know" → "how the user knows".
6. **Data model:** add `tree id` to Person, Relationship, Place, Pin and Source; PlaceName notes "Follows its Place's Tree"; new rows Account, Tree and TreeAccount (one row in v1, no roles). One sentence after the table: Polity, PolityName, PolityParent and BoundaryVersion carry no tree id (NFR-09).
7. **NFRs:** add NFR-09 (Must): sign-in is an Account; people, relationships, pins, sources and places belong to a Tree; boundaries, polities and historical maps are shared by all Accounts.
8. **M2:** add NFR-09, then the three Intent checks as sub-bullets.
9. **M4:** "my family" → "the user's family".
10. **Open questions:** tick "Hosted or local-first?" as hosted (#13).

"Not in v1: sharing or multiple users" stays.
