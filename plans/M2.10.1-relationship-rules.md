# Plan: M2.10.1: Relationship rules

- **Spec:** #535
- **Requirement IDs:** [PPL-02](../docs/requirements.md#ppl-02)
- **Status:** draft

## Approach

A branded `RelationshipId` joins `lib/domain/ids/`. `lib/domain/relationships/` holds the types, `relationshipInputSchema` and `checkRelationship`. The schema is a Zod discriminated union on `type` of two strict objects, so a parent with no subtype or a spouse with a subtype fails. A spouse refinement refuses a divorce whose `latestDay` is before the marriage's `earliestDay` (D4).

`checkRelationship(input, existing)` returns a `Result` with the refusal `self`, `duplicate`, `third-biological-parent` or `cycle`, in that order. It first drops the Relationship in `existing` with the id of `input`, so one function serves create and update. The cycle rule maps each parent to its children, then walks down from the new child. It refuses if the walk reaches the new parent. The walk is linear in the parent Relationships.

The date and id fields of `personInputSchema` move to shared helpers, so both schemas use one copy. M2.10.2 (#771) stores the types, and M2.10.3 wires `checkRelationship` through `openTree`.

## Decisions

**D1 · Relationship fields** · Decides: Tech lead

Which field names does a Relationship have? M2.10.2 makes its table from them.

- **A.** Names per type. A parent has `parentId`, `childId` and `subtype`. A spouse has `personAId`, `personBId`, `marriage` and `divorce`. M2.10.2 maps them to the columns of the requirements' data model.
- **B.** One set for both types, as in the requirements' data model: `personA`, `personB`, `subtype`, `start` and `end`. In a parent Relationship, A is the parent of B.
- **Other:** your own.

Recommended: A, because a reader of the rules or the screens does not need to know which Person is A.

## Alternatives considered

- Copy the date field into the new schema: the [code rules](../docs/code-rules.md) forbid a copied helper.
- A depth-first walk by recursion: a deep Tree can overflow the stack. The walk uses a queue.

## Risks

- The rules accept A as both the parent and the spouse of B. The Spec does not refuse it.
- The Spec does not rank the refusals. The order in [Approach](#approach) decides which one shows when two apply.
