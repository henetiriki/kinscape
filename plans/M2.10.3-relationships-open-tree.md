# Plan: M2.10.3: Relationships in openTree

- **Spec:** #772
- **Requirement IDs:** [PPL-02](../docs/requirements.md#ppl-02), [NFR-09](../docs/requirements.md#nfr-09)
- **Status:** draft

## Approach

`openTree` gains a `relationships` group beside `persons`, built over the M2.10.2 store methods. `list` and `get` pass each row through a new `relationshipView`. In v1 this view hides nothing.

`create` and `update` read the Tree's Relationships with `listRelationships`, then run `checkRelationship` (M2.10.1). A refusal returns as the error, and the group calls no write. If all rules pass, the group calls `addRelationship` or `updateRelationship`. The store then gives `not-found` for a Person outside the Tree, and `conflict` for a stale version.

The #535 note: `checkRelationship` drops the Relationship with the input's id. This is safe here for two reasons. The store finds the update's row by Tree, id, type and both Persons (M2.10.2 D1 A). A repeated create id saves nothing.

## Decisions

**D1 · Which error an update gives when it is stale and also breaks a rule** · Decides: Tech lead

An update can name a stale version, or a missing id, and also break a rule. Which error does the group return?

- **A.** The refusal. The group runs the rules first, then the store. This is one read and one write.
- **B.** `conflict` or `not-found`. The group reads the saved row with `findRelationship` first, then runs the rules. This adds one read. The store still checks the version on the write.
- **Other:** your own.

Recommended: A, because M2.11 shows either error, and the store check on the write stays the guard in both options.

## Alternatives considered

- A per-Tree lock for the cycle race: the Spec flags the race as unlikely.
- Rules inside each store adapter: the store applies no rules (M2.10.2), and two adapters would copy the logic.

## Risks

- A request that names the same Person twice and a Person outside the Tree gives `self`, not `not-found`. The rules run before the store.
- Each write reads every Relationship of the Tree. M2.10.2 sized this at about 4,000 rows.
- The concurrent cycle race stays as the Spec flags it. This plan writes no lock.
