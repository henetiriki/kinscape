## Order of work

1. Record D1. Commit the approval.
2. The tech lead links the repository on this branch and pastes the Spec's prompt on the canvas.
3. The tech lead runs the refresh steps 5.1 to 5.5 and commits `design/canvas/` alone.
4. Check each new board against Behaviour and UX and the Acceptance checks. List each mismatch in the PR.
5. Add the `export.json` entries, the `DESIGN.md` rows and the test changes.
6. Run `npm run design-system` (D1).
7. Push. Run `gh workflow run design-agent-shots.yml --ref spec/M2.11.1-relationship-screens-design`. If GitHub denies it, ask the tech lead.
8. Pull the shots commit. Run all checks. Paste the output.
9. In the PR body, list the boards, the layout and each hand-drawn part with its states.

## Risks

- **Board drift:** if the shots commit changes a built snapshot, stop.
- **Colour check:** the export refuses a colour that is not a token. Ask the design agent to fix the board.
- **Word budget:** the 15 rows may pass the 4,000 words of `DESIGN.md`. Then stop and ask the tech lead.
- **Refusal name:** the Spec writes `biological parents`. The code is `third-biological-parent` (`lib/domain/relationships/types.ts`). M2.11.2 maps it.
