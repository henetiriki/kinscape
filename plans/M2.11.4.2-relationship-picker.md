# Plan: M2.11.4.2: Relationship picker

- **Spec:** #845
- **Requirement IDs:** [PPL-02](../docs/requirements.md#ppl-02), [NFR-05](../docs/requirements.md#nfr-05)
- **Status:** draft

## Approach

The route reads the Relationships and every Person through `treeAction` (D2). It sends the other Persons as `PersonSummary` rows. "Add" in `PersonRelationships` opens a new client part, `RelationshipPicker`. The picker is a `Dialog` titled "Add a parent", "Add a spouse" or "Add a child", as the canvas says. It filters with the People list's function, which moves to `lib/domain/persons/list.mts` so both use it. Three `/screens` routes open the picker with the board's synthetic Persons and filter.

## Decisions

**D1 · The order of the picker rows** · Decides: Tech lead

The `relationship-pick` board lists Fourie, Botha, Foury: the order of its sample data.

- **A.** Sort by surname, then given names, as the People list and the groups do. The build sorts the matches on the board and bumps `design/canvas/VERSION`. The Render workflow renders the snapshots.
- **B.** Keep the order of the Tree's list. The screen data follows the board.
- **Other:** your own.

Recommended: A, because a user then finds a Person at one place in each list.

**D2 · When the page reads the other Persons** · Decides: Tech lead

- **A.** With the Relationships, in one `persons.list()`. A failed read shows the page's load-failed notice. The groups take the related Persons from this list, so `relatedPersonIds` goes.
- **B.** A server action when the picker opens. The picker then needs a loading state and a failed state. No board draws them.
- **Other:** your own.

Recommended: A, because the People page reads the same list, and B needs states with no board.

## Order of work

1. Move the filter and the row mapper, test first.
2. Write `RelationshipPicker`, then wire "Add" and the route, each with its test.
3. Write the screens. Run `/match-design` on each board.
4. Run the checks in `AGENTS.md`.

## Risks

- At 2,000 Persons the page sends 2,000 rows, as the People page does. An empty filter draws them all. The dialog body scrolls.
- "Add a person" leaves the page for `/people/new`, as the board's link does.
