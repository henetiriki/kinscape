# Plan: M2.11.5.1: Relationships link on the edit page and the People list

- **Spec:** #827
- **Requirement IDs:** [PPL-02](../docs/requirements.md#ppl-02), [NFR-05](../docs/requirements.md#nfr-05)
- **Status:** approved

## Approach

`PersonForm` shows a `TextLink` "Relationships" at the end of its heading row when it has a `person`. The desktop rows of `PeopleList` pass `relationshipsHref` to `PersonRow`, which already draws the link. The phone rows and `/people/new` pass nothing, and `EditOnComputer` already hides the form on a phone. The `/screens` routes for the four snapshots use these components, so they show the link with no change. A local session swaps the boards and removes the two copies.

## Order of work

1. The CI build writes the two component changes and their tests, test first, and the e2e checks. It pushes and asks in the PR for step 2. The PR stays a draft.
2. A local session that the tech lead starts runs the prompt below. Then it runs "Refreshing the canvas copy" (5.1 to 5.5). In one commit it makes the `DESIGN.md`, `NOT_BUILT` and count edits and the D1 deletions. It runs `npm test` and pushes.
3. The tech lead runs the workflow Design: Render snapshots.
4. The build runs `/match-design` on `people-list` and `person-edit`, then the checks in `AGENTS.md`.

The prompt is the [board swap prompt](../design/COMPONENTS.md#board-swap-prompt), with these lines:

```text
The boards use only components that the canvas has. Change no file under ds/.
In Person-new.dc.html, add a KinScape.TextLink "Relationships" with href="Person-relationships.dc.html" to the edit, save-failed and conflict variants.
Put it at the end of the heading row, as Person-edit-relationships.dc.html does. Give it no on-click.
The new and errors variants get no link.
In People-list.dc.html, give each KinScape.PersonRow relationships-href="Person-relationships.dc.html".
Add an empty header cell above the links, so Name and Dates stay above their columns.
Delete People-list-relationships.dc.html.
In design/canvas/export.json, delete the entries person-edit-relationships and people-list-relationships.
Keep Person-edit-relationships.dc.html and Person-edit-relationships-leave.dc.html.
The person-new, person-errors, people-list-no-match, people-empty and people-load-failed snapshots must not change pixels.
```

## Risks

- **Unsaved changes go.** Until M2.11.5.2, the edit page link drops an edit with no warning. The Spec accepts this.
- **The header.** The link has no fixed width, so the header cell can be off by a few pixels. `design:check` on `people-list` finds it.
- **`DESIGN.md` is a design system input.** The edit touches only the Screens tables, which are not in `README_SECTIONS`. So `npm run design-system` gives no change, and steps 3 to 5 of the design system do not run.
- **`design:check` fails** on the four screens between steps 1 and 3.
