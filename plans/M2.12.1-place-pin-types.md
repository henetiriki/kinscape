# Plan: M2.12.1: Place and Pin types and schemas

- **Spec:** #537
- **Requirement IDs:** [PIN-02](../docs/requirements.md#pin-02), [PIN-03](../docs/requirements.md#pin-03)
- **Status:** approved

## Approach

`PlaceId` and `PinId` join `lib/domain/ids/` as `RelationshipId` did: a brand, and a parse function that lower-cases a UUID. `lib/domain/places/` holds `placeInputSchema` and its types. `lib/domain/pins/` holds `pinInputSchema` and its types. Each schema is a Zod strict object, so a client-sent Tree id or other key fails.

A Place has `id`, `latitude` (-90 to 90), `longitude` (-180 to 180) and `precision`. `PlacePrecision` is a new type with the nine PIN-02 codes: `street`, `building`, `erf`, `farm`, `suburb`, `town`, `district`, `province` and `approximate`. `street` is street address and `town` is town or city. `Precision` does not change (Spec D1).

A Pin has `id`, `personId`, `placeId`, `address`, `eventType`, `date`, `sources` and `notes`. `date` is required (Spec D2). A new `requiredFuzzyDate` in `lib/domain/dates/schemas.mts` parses GEDCOM text and fails on blank text. It shares its parse step with `fuzzyDateText`. `eventType` takes the ten PIN-03 codes (D4). The address, sources and notes default to the empty string.

The text field of `personInputSchema` trims, caps and refuses a NUL character. It moves to `lib/domain/text/schemas.mts` as `textField(max)`, so Person and Pin use one copy. The limits are in D5.

M2.12.2 (#879) wires `placeInputSchema` into its store. M2.12.3 (#880) wires `pinInputSchema`.

## Decisions

**D4 · Where the Event type codes live** · Decides: Tech lead

`EventType` is on `main` in `lib/ui/types.ts`, from the keys of `EVENT_PATHS` in `lib/ui/EventGlyph.tsx`. The layer map lets `lib/domain` import only itself. It lets `lib/ui` and `app/components` import no `lib/domain` code. So the Pin schema cannot use the `lib/ui` type.

- **A.** `lib/domain/pins/` lists the same ten codes as `EVENT_ORDER` (`land` is land ownership, `baptism` is baptism or christening). `pins/types.ts` exports a new `EventType`. A test checks that the two lists are equal. This keeps two copies of one list.
- **B.** Let `lib/ui` and `app/components` import `lib/domain`. The domain owns the list, and `lib/ui` imports its type. This edits `scripts/layers.mts` and `docs/architecture.md`. `scripts/layers.mts` is a hand-back path, so the tech lead builds the PR.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D5 · Field limits** · Decides: Tech lead

Spec D3 lets the plan set the numbers. Person has `MAX_NAME` (200) and `MAX_NOTES` (10,000).

- **A.** Address 500, sources 10,000, notes `MAX_NOTES` (10,000). A deed can name an erf, a portion, a farm and a district in one address, and 200 characters can cut it.
- **B.** Address `MAX_NAME` (200), sources and notes `MAX_NOTES`. No new constant.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D6 · A Place with no precision** · Decides: Tech lead

The Spec sets the nine precision values but not a missing one. A click on the map gives no precision.

- **A.** Precision is required. The Pin form (a later Spec) must preselect a value.
- **B.** Precision defaults to `approximate`, as `sex` defaults to `U` on a Person.
- **Other:** your own.

**Answer: B** (@henetiriki)

## Alternatives considered

- Reuse `fuzzyDateText` with a refinement: the output type stays `FuzzyDate | undefined`, so each reader must check again.
- Copy the text field into the Pin schema: the [code rules](../docs/code-rules.md) forbid a copied helper.

## Order of work

1. The ids and `textField`, test first. The persons tests stay green.
2. `requiredFuzzyDate` tests, then the field.
3. Place schema tests for each acceptance check, then the schema.
4. Pin schema tests for each acceptance check, then the schema.
5. The checks in `AGENTS.md`.

## Risks

- At run time a Place id is any UUID, so a Person's UUID sent as a `placeId` parses. The branded types stop the mix-up at compile time. M2.12.3 checks that the Person and the Place are in the Tree.
- A form posts a latitude as text. This schema takes a number, so the form action converts it first.
