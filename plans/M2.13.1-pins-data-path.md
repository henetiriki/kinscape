# Plan: M2.13.1: Pins data path

- **Spec:** #538
- **Requirement IDs:** [PIN-02](../docs/requirements.md#pin-02), [NFR-01](../docs/requirements.md#nfr-01), [NFR-03](../docs/requirements.md#nfr-03), [NFR-10](../docs/requirements.md#nfr-10)
- **Status:** approved

## Approach

A new route handler, `app/data/pins/route.ts`, answers `GET`. It calls `currentSession()` first, because the gate fitness test needs a session check in each route file. With no session it answers 401 with no body, as `/data/polities` does.

The route then reads the Tree through `treeAction` (`server/action.mts`), which calls `openTree`. The scoping rule lets `app/` reach `appAdapters` only through `treeAction`. The body calls `pins.list` and `places.list`, and returns `mapPins(pins, places)`. The route sends the result through `privateJson()` and sets no header itself.

`mapPins` is a pure function in `lib/domain/pins/map-pins.mts`. It puts the Places in a `Map` by id, so the join is one pass over each list (the scale rule in `docs/code-rules.md`). Each `MapPin` holds `eventType`, `id`, `latitude`, `longitude` and `span`. The position uses the field names of `Place`. It holds no `placeId`, `personId`, `date`, `address`, `sources`, `notes` or `version`. The function drops a Pin whose Place is not in the list.

The browser side adds `@tanstack/react-query` at an exact version, as `package.json` pins each package. `app/QueryProvider.tsx` makes one `QueryClient` for each browser page load, held in `useState`. The root layout wraps its children and the `@map` slot in it, so the map and later screens share one cache.

`features/pins/query.ts` holds `fetchPins` and `usePins`. `usePins` calls `useQuery` with the key `['pins']` and `staleTime: Infinity`, so the Pins load once. `fetchPins` throws on a response that is not OK, so the query shows its error state. The plan adds no persistence plugin.

If a route handler throws, it logs the error name only, and answers 500 with no body. A message can hold Person data. `unstable_rethrow` lets Next's own errors pass, as the People page does.

`usePins` has no caller in this Spec. M2.13.2 (#859) wires it to the map.

## Decisions

**D3 · The answer when a session passes but `openTree` gives `not-found`** · Decides: Tech lead

The session can end between `currentSession()` and `openTree`, or the Account can have no Tree. #861 gives one answer to every unknown Pin.

- **A.** 401 with no body, the same answer as a signed-out request. The browser handles one refusal.
- **B.** 404 with no body. The browser handles two answers.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D4 · Where the query layer lives** · Decides: Tech lead

TD.2 (#1091) names the path of the query layer that this Spec builds, and it reads the path from `main`. M2.13.2 (#859) feeds the Pins layer from this query. A feature may not import another feature (`docs/architecture.md` › Layers).

- **A.** `features/pins/query.ts`, exported by `features/pins/index.ts`. The table in `docs/architecture.md` puts a feature's queries in `features/<name>/`. #859 builds its layer in `features/pins/layers/`. A later feature adds its own query file to the list of #1091.
- **B.** A new shared folder, `lib/query/`, that every feature imports. It adds a row to the Layers table and to `scripts/layers.mts`, about 30 lines. #1091 then names one folder. #859 imports from it.
- **Other:** your own.

**Answer: A** (@henetiriki)

## Alternatives considered

- The route calls `openTree` directly: the scoping rule lets `app/` import `appAdapters` only through `server/action.mts`.
- A position as `[longitude, latitude]`: it adds a second name for the fields of `Place`. #859 builds the GeoJSON order from the two fields.
- Global `staleTime: Infinity` on the `QueryClient`: it also applies to later queries, such as the Pin details of #861.

## Risks

- The payload grows with the Tree. `listPins` and `listPlaces` stop at `MAX_PINS` and `MAX_PLACES` (10,000 each). At 10,000 Pins the body is about 1.3 MB before compression.
- A Tree with more than 10,000 Places, and a Pin on a Place past the cap, loses that Pin from the map. No screen makes a Place without a Pin today. A fix costs about 20 lines: a `places` read by the ids of the Pins. The plan does not build it.
- #863 D1 is open. Its option B adds the Place id to this payload, and changes the exact-keys test of this Spec.
- M2.14.3 (#866), M2.14.6 (#869) and M2.15.2 (#884) load the Pins query again after a save, with the key `['pins']`. This Spec adds no reload helper, because nothing calls one yet.
