# Plan: M2.13.2: Pins on the map by Map date

- **Spec:** #859
- **Requirement IDs:** [PIN-03](../docs/requirements.md#pin-03), [PIN-06](../docs/requirements.md#pin-06), [NFR-01](../docs/requirements.md#nfr-01)
- **Status:** approved

## Approach

A new client file, `app/@map/MapWithPins.tsx`, calls `usePins` and builds the layers with `useMemo([polityLayer, pinsLayer(pins)])`. It renders `MapShell`. The page renders it in place of `MapShell`. Until the Pins load, the layer holds no feature, so the "Pins" row is on from the first render.

`pinsLayer(pins)` in `features/map/layers/pins.ts` is pure. It makes one GeoJSON point per Pin at `[longitude, latitude]`, with `eventType`, `validFrom` and `validTo`. Its one symbol layer, `pins`, draws the icon `pin-<eventType>` in `map.pin.colour`, with a halo of `map.pin.halo` and `map.pin.halo-width`. `icon-allow-overlap` and `icon-ignore-placement` are on, so Pins on one Place overlap (PIN-06). Its filter is `spanFilter(day)`, which `features/map/filter.ts` takes from `dateFilter`. Its caption is "N of M true on this date". N counts the Pins whose span holds the day under `isCurrentOn`, in one pass.

`Layer` gets two changes:

- `description` can be a function of the Map date. `LayersList` takes `day` from `MapShell` and calls it.
- An optional `icons` record maps an image id to a 24 × 24 path (`EVENT_PATHS`).

`MapView` gets two generic effects, so it still names no layer:

- On `styleimagemissing`, it finds the id in the `icons` of a layer. It draws the path on a canvas (`features/map/icons.ts`), changes the alpha to a signed distance field (`lib/domain/map/sdf.mts`) and calls `addImage(id, image, { sdf: true })`. DESIGN.md › Event glyphs asks for SDF icons, and only an SDF icon takes a halo.
- When `layers` changes, it calls `setData` on each GeoJSON source whose `data` is an object it has not applied yet. A Map date change only sets filters (NFR-01).

A failed load shows an error `Toast`, "Your pins did not load.", with "Try again", which calls `refetch` (D2: B). `MapShell` gets a `toast` slot. Its stylesheet puts the toast at the bottom centre, above the dock (DESIGN.md › Toast). On a phone the toast is `placed`. Esc hides it until the next error.

`scripts/seed-ci.mts` adds 10 Persons with no birth or death, 500 Places and 10,000 Pins (D1: A). It calls `addPerson`, `addPlace` and `addPin` of `databaseStore`, with fixed ids, so a second run adds nothing. The Pins cycle through the ten event types, and their spans run from 1700 to 2015. Pin 0 is a residence `FROM 1840 TO 1855`. The config ignores the specs that need the seed unless `KINSCAPE_MEMORY_SIGN_IN` is `1` (D9).

## Decisions

**D6 · Where the Pins layer lives** · Decides: Tech lead

A feature may not import another feature, also for a type (`scripts/layers.mts`). `Layer` is in `features/map/types.ts`, and `usePins` is in `features/pins`. The #538 plan (D4: A) says that #859 builds its layer in `features/pins/layers/`.

- **A.** `features/map/layers/pins.ts` exports `pinsLayer(pins)`. `app/@map/MapWithPins.tsx` joins it to `usePins`. This is the _Where does X go_ row: routes pass layers to `MapShell`. No layer rule changes.
- **B.** Move `Layer`, `DrawingLayer` and `LayerId` to a new shared folder outside `features/`. Add a row to `scripts/layers.mts` and to the Layers table. Put the layer in `features/pins/layers/pins.ts`. About 40 more lines.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D7 · The size of a Pin on the map** · Decides: Tech lead

DESIGN.md and `design/tokens.json` give no size for a Pin symbol. No board draws a single Pin. `map-pin-fan` draws each glyph at 22 px, inside a white 36 px chip. M2.13.5 (#863) draws that fan.

- **A.** 22 px, as the glyphs of `map-pin-fan`. A literal in `pins.ts`. #863 adds a token if its fan shares the value.
- **B.** 24 px, the glyph's own box. A literal in `pins.ts`.
- **C.** A new `map.pin.size` token, through [Changing the design system](../design/CANVAS.md#changing-the-design-system). The tech lead or a local session runs steps 3 to 5.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D8 · The diff passes the 600-line cap** · Decides: Tech lead

The Spec estimates 650 lines. This plan comes to about 850: 350 of code and 500 of tests. The SDF icons add about 200 lines, the seed about 90.

- **A.** One PR, as this plan says.
- **B.** Split the SDF icons (`icons`, `icons.ts`, `sdf.mts` and the `MapView` effect) into a Spec that this one waits for. Two PRs, of about 250 and 600 lines.
- **C.** Draw each icon on the canvas in `map.pin.colour` with a 2px stroke in `map.pin.halo`, with no SDF. About 100 lines less. A later colour, such as `map.selected`, then needs a second set of images. DESIGN.md says SDF, so this needs a Bug against DESIGN.md.

## Alternatives considered

- A sprite sheet made at build time: it adds a generator and generated files, and `EVENT_PATHS` already has a test that keeps it in step.
- The page counts the caption: `MapShell` holds the Map date, so the layer's function is the one place that knows both.
- A `kind: 'pin'` property for `dateFilter`: it adds a property to 10,000 features for no gain.

## Risks

- `navigation.spec.ts` starts the map twice in up to 26 s of 30 s. The 1.3 MB of Pins in each map load can pass the limit. If it does, the test gets `test.slow()`, as its comment allows.
- The seed makes about 30,000 queries. It can add 30 s to the `e2e` job.
- The seed fills `MAX_PINS` (10,000). A later e2e test that adds a Pin to the SYNTHETIC Tree loses one Pin past the cap.
- No `chromium` e2e test counts the Persons or Pins of the SYNTHETIC Tree. The `fixture` and `design` projects use the memory adapters.
- A symbol layer of 10,000 points places its symbols again on each filter change. If the `@perf` check fails, the plan stops for the tech lead.

## Deviations

- `MapView` calls `setMissingStyleImageResolver`, not `on('styleimagemissing')`. MapLibre fires the event after the tile layout, so the first draw has no icon. The resolver runs before the layout.
- `fixture-pins.spec.ts` also holds two tests: a `page.route` response with one Pin of each Event type (proves the SDF images in a real browser), and the error toast of the `r.failing` Account. The `@perf` check still reads the seeded Postgres.
- `docs/architecture.md` changes: the _Temporal validity_ and _Map layers_ rows.
- `scripts/word-count.mts` and its test raise the `docs/architecture.md` limit to 1020 (D11).
- `playwright.config.ts` and `e2e/types.ts` change (D9, D10). Three older specs import `TestWindow`.
- `icons.ts` sets the field radius to `8 * ratio`, as `SDF_PX` of MapLibre is 8.
- The `IconImage` type is in `features/map/types.ts`, as the lint rule asks.
- The existing `seed-ci.test.ts` tests pass a size of 0, because the default size takes minutes on PGlite.
