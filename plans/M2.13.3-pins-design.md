## Approach

The CI agent cannot sign in. The tech lead, or a local Claude Code session that the tech lead starts, pastes the Spec's prompt on the canvas. The same person runs the [refresh steps](../design/CANVAS.md#refreshing-the-canvas-copy) and "After the canvas" of the Spec. The workflow Design: Render snapshots makes the snapshots and the JPGs. The PR adds no app code and no `design/screens.json` entry. `DESIGN.md` gets only Screens rows, so the design system steps do not run unless the README check of Spec D8 fails.

## Decisions

**D1 · The click popup of M2.14.1 and `Popup`** · Decides: Tech lead

#539 › Flagged concerns says: "The click popup of this Spec must look like it. The two popups share `Popup`." This Spec says that `Popup` does not fit a Pin popup, and draws `draft-pin-popup`. #868 builds the click popup from `pin-click-popup` of #539.

- **A.** The build rewords the Components line of #539 › Behaviour: the click popup takes the frame of `draft-pin-popup`, not `Popup`. Cost: one reword. #868 does not change.
- **B.** Leave #539. M2.14.1 picks the frame when it draws. Cost: the two popups can differ.
- **Other:** your own.

Recommended: A, because #539 already wants the click popup to look like the Pin popup.

**D2 · Who deletes the four Drafts boards** · Decides: Tech lead

`design/COMPONENTS.md` step 4 deletes a Drafts board after the swap of its built part. #862 › Behaviour builds the popup in `CONTROLS` and names no Drafts board. #863 › Behaviour builds the marker or the fan as a component only "if one is" shared, and names no Drafts board.

- **A.** The build rewords the "Design system" line of #862 and #863. #862 builds from `draft-pin-popup` and `draft-pin-popup-phone`, and deletes them. #863 builds from `draft-pin-marker` and `draft-pin-fan`, and deletes them, also if it builds map layers and no component. Cost: two rewords.
- **B.** Leave #862 and #863. The Flagged concerns of this Spec hold the rule. Cost: a build Spec can leave a Drafts board with no owner.
- **Other:** your own.

Recommended: A, because each build Spec then names the boards that it deletes.

## Order of work

1. Record the answers of D1 and D2. Commit the approval.
2. Reword the issues that the answers name ([reword step](../.github/agent/build.md#reword)).
3. Link the repository on `spec/M2.13.3-pins-design`. Paste the Spec's prompt on the canvas.
4. Run the refresh steps 5.1 to 5.5. Commit `design/canvas/` alone.
5. Check each new board against Behaviour and UX and the Acceptance checks. List each mismatch in the PR.
6. Add the `export.json` entries, the `DESIGN.md` rows and the test changes. Each Drafts viewport takes the `w` and `h` of its board in `canvas.json`.
7. Run `npm run design-system`. Compare the sha256 of `.design-system/project/README.md` and `design/canvas/project/ds/kinscape/README.md`. If they differ, stop and ask the tech lead (Spec D8).
8. Push. Run `gh workflow run design-agent-shots.yml --ref spec/M2.13.3-pins-design`. If GitHub denies it, ask the tech lead.
9. Pull the shots commit. Run all checks. Paste the output.
10. In the PR body, list the boards, the layout and each hand-drawn part with its states.

Steps 3 to 9 need a signed-in account: the tech lead, or a local Claude Code session that the tech lead starts.

## Risks

- **Board drift:** if the shots commit changes a built snapshot, stop.
- **Colour check:** the export refuses a colour that is not a token. Fix the board.
- **Word budget:** if the 11 rows pass the 4,150 words of `DESIGN.md`, stop and ask the tech lead.
- **Static image:** the boards show the fan open. The design check does not see the hover, the tap or the motion.
- **Focus look:** #862 D1 and #863 give the map no keyboard access in M2. The count marker's focus look has no use until a later Spec adds it.
