## Approach

A local Claude Code session that the tech lead starts draws the 17 boards. It follows [Drawing a board](../design/CANVAS.md#drawing-a-board) and step 7 of [Changing the design system](../design/CANVAS.md#changing-the-design-system). The CI agent cannot sign in to claude.ai, so it runs no drawing step. The workflow Design: Render snapshots makes the snapshots and the JPGs. The PR adds no app code and no `design/screens.json` entry. `DESIGN.md` changes only in Screens and "Not designed yet", which `README_SECTIONS` does not list. Steps 3 to 5 run only if the README check fails.

## Decisions

**D1 · The coordinates in `pin-form`** · Decides: Tech lead

`pin-form` is the panel after a click. #868 fills the coordinates "in decimal degrees with 6 decimals". The Spec gives the format as "-33.93, 18.42". #866 reads both.

- **A.** `pin-form` shows 6 decimals, such as "-33.925800, 18.423200". The other boards show 2 decimals, as a user types them. #868 does not change.
- **B.** Every board shows 2 decimals. Cost: the build of #868 shows a value that no board draws.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D2 · The messages of `pin-form-errors`** · Decides: Tech lead

A field shows one message at a time. The Spec names seven messages for four fields. #866 adds an address over 500 characters. #867 adds a source or a note over 10,000. #540 adds a latitude of 91 or a longitude of 181.

- **A.** The board shows one message on each field that has one: a missing Person, a missing event type, a date that does not read, the decimal-degrees message, and the length message of the address, the sources and the notes. The PR body gives the text of each other message: a missing date, a missing point, coordinates that do not read, and a point out of range. #866 and #867 do not change.
- **B.** The board shows only the four fields that the Spec names. The PR body gives the text of each other message. Cost: #866 and #867 build their length messages with no board.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D3 · The saving look of "Save"** · Decides: Tech lead

`Button` has no saving state. `PersonForm` and `RelationshipDetails` disable "Save" while they save.

- **A.** `pin-form-saving` shows "Save" disabled, as the Person form does. No new part.
- **B.** "Save" shows a label such as "Saving…". Cost: a fourth hand-drawn part with no Drafts board (Spec D12), and a later change to `Button`, a design system input.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D4 · The error look of the event type, the sources and the notes** · Decides: Tech lead

`SelectField` and `TextAreaField` have no `error` prop and no marked state. D2 A needs an error on the event type, the sources and the notes. The build found this after the approval of the plan.

- **A.** Each board puts a small `Text` (tone error) under the field. No red border and no icon. No new part. The PR body flags the gap. M2.14.3 and M2.14.4 add an `error` prop to both components.
- **B.** A fourth Drafts board, `draft-pin-field-errors`, draws the marked error look of both fields. The screen boards use it. Cost: the plan and the Spec change to 17 boards and 90 snapshots, and the tech lead approves the plan again (a big departure). M2.14.3 and M2.14.4 build the look and delete the board.
- **Other:** your own.

**Answer: B** (@henetiriki)

## Order of work

1. Record the answers of D1 to D3. Commit the approval.
2. On `spec/M2.14.1-add-a-pin-design`, draw each board in `design/canvas/project/` as Drawing a board says. Put the screen boards on the Map page, beside `Add-pin.dc.html`, and the four parts on Drafts.
3. Check each board against Behaviour and UX, the Acceptance checks and D1 to D3. List each mismatch in the PR.
4. Add the `canvas.json` and `export.json` entries. Each Drafts viewport takes the `w` and `h` of its board.
5. Run steps 7.2 to 7.5 of Changing the design system. Publish `canvas.json` last.
6. Add the `DESIGN.md` rows and line, `NO_ENTRY` and the two counts.
7. Run `npm run design-system`. Compare the sha256 of `.design-system/project/README.md` and `design/canvas/project/ds/kinscape/README.md`. If they differ, stop: steps 3 to 5 apply.
8. Push. Run `gh workflow run design-agent-shots.yml --ref spec/M2.14.1-add-a-pin-design`.
9. Pull the shots commit. Run all checks and `npm run design:check`. Paste the output.
10. In the PR body, list the board files and the layout, and each hand-drawn part with its states. List each value with no token, and the message texts of D2.

Steps 2 to 9 need a signed-in account: the tech lead, or a local Claude Code session that the tech lead starts.

## Risks

- **Board drift:** if the shots commit changes a built snapshot, stop.
- **Colour check:** the export refuses a colour that is not a token. Fix the board.
- **JPG frame:** `shotFor` shoots each JPG at 1440 × 900 by name. Keep each Drafts board inside that frame. The JPG shows it at the top-left, as in M2.13.3.
- **No component:** if the panel shell or the loading look needs a part with no component, stop and ask. Spec D12 and D4 allow four Drafts boards only.
- **Word budget:** if the 17 rows pass the 4,400 words of `DESIGN.md`, stop and ask the tech lead.
- **Build gap:** #866 builds five of the eight fields, but its boards show eight. #867 adds the other three. #866 then fails its design check unless its plan decides how.
- **Board name:** `map-add-pin` does not match `pin-*`. The Screens table names it. The "Not designed yet" line keeps the words of Spec D13.
- **Static image:** the boards show each panel open. The design check does not see Esc, hover or the live reading as it changes.
