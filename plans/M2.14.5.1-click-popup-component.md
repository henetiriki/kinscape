# Plan: M2.14.5.1: Map click popup

- **Spec:** #1187
- **Requirement IDs:** [PIN-01](../docs/requirements.md#pin-01)
- **Status:** approved

## Approach

A new shared part, `ClickPopup` (`app/components/overlays/`), draws the popup of `draft-pin-click-popup`. It takes `point` (`latitude`, `longitude`), `x` and `y` (px from the corner of the overlay area), `onAdd(point)` and `onClose`. It sits in `PlacedAt` with `popup-gap` (#539 D15 A), and it takes the frame of `PinPopup` (#539 D14 A, D3). A private `pointText` in `ClickPopup.tsx` writes "latitude, longitude" with `toFixed(6)` (Spec D2 A). #868 exports it for the coordinates field. The build adds the part to `CONTROLS`, writes one card state and the Components text, and adds a dev page `/screens/pin-click-popup` on `MapFrame` (Spec D1 A). A local session that the tech lead starts runs steps 3 to 7 of [Changing the design system](../design/CANVAS.md#changing-the-design-system). That session also deletes the draft board.

## Decisions

**D3 · The frame of the click popup** · Decides: Tech lead

#539 D14 A gives the click popup the frame of `PinPopup`. #539 says that the Spec that builds the popup decides whether the two popups share one frame. #1187 does not decide this. On `main`, `Floating` in `PinPopup.tsx` holds the surface, the padding, the 304px width, the pointer and the Esc handler. It is private.

- **A.** `PinPopup.tsx` exports its frame with an `aria-label` prop. `ClickPopup` uses that frame. Cost: about 15 lines, and the `PinPopup` tests run on the moved frame.
- **B.** `ClickPopup` has its own frame. Its CSS takes `.popup` of `PinPopup.module.css` with `composes`. Cost: a third copy of the Esc handler and the pointer markup.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D4 · The point dot** · Decides: Tech lead

A note of `draft-pin-click-popup` says: "The point shows as a 12 px dot in --brand with a white edge." The board `pin-click-popup` draws the dot in its map svg. #1187 and #868 do not say which part draws the dot in the app.

- **A.** `ClickPopup` draws the dot at `x`, `y` beside the popup: 12px, `--brand`, a 2.5px `--surface` edge. #868 gets the dot with the popup. The step 7 swap removes the svg dot from the `click-popup` variant of `Map-add-pin.dc.html`. Cost: about 15 lines.
- **B.** The Components text holds the dot note only. #868 draws the dot as a map layer. Cost: about 40 lines in #868, which names no dot.
- **Other:** your own.

**Answer: A** (@henetiriki)

## Alternatives considered

- `pointText` in `lib/domain/places/coordinates.mts`, beside `parseCoordinates`: the layer table bars `app/components` from `lib/domain`. The popup would then need the text and the point as two props.
- A `PlacedClickPopup` beside a `ClickPopup`: the Spec asks for one card state, so one part takes `x` and `y`.

## Order of work

The CI build agent does steps 1 and 2. A local Claude Code session that the tech lead starts does steps 3 to 7, with a signed-in account. The build keeps the PR a draft until then.

1. Write the `ClickPopup` test, see it fail, then build the part (D3, D4). Commit with its test.
2. Add the `CONTROLS` entry, the card state, the sample and the Components text. Add the dev page, its test, the `screens.json` entry and the test list changes. Run `npm run design-system`.
3. Run `/publish-design-system` (3.1 to 3.11).
4. Run "Updating the install" (4.1 to 4.6).
5. Run "Refreshing the canvas copy" (5.1 to 5.5).
6. Step 6 does not run: the board `pin-click-popup` shows the change.
7. Run step 7 on `Map-add-pin.dc.html` with the [board swap prompt](../design/COMPONENTS.md#board-swap-prompt). In the same session, delete the draft board from the canvas and from the repo copy. Remove its records, snapshot and JPG. Then run the workflow Design: Render snapshots once.

## Risks

- `Map-add-pin.dc.html` is the base file of 13 boards. Only the `click-popup` variant uses the hand-drawn popup. The export after the swap must change only `pin-click-popup`. The session reports any other changed snapshot.
- Until step 7, the board shows 2 decimals and the page shows 6, so `npm run design:check` can fail on `pin-click-popup` (Spec, Flagged concerns). The PR stays a draft until the workflow run.
- The design check hides the board's map svg and the dot in it. The dot of the page (D4 A) falls inside that hidden area, so the check does not prove the dot. The part test and the card image prove it.
