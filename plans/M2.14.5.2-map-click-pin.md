# Plan: M2.14.5.2: Map click starts a Pin

- **Spec:** #868
- **Requirement IDs:** [PIN-01](../docs/requirements.md#pin-01), [NFR-05](../docs/requirements.md#nfr-05)
- **Status:** approved

## Approach

`MapView` gives `onEmptyClick` the clicked `{ latitude, longitude }` from the MapLibre event (Spec D5 A). It also follows a new `clicked` position, as it follows the open Pin, and reports the pixel point through `onOpenPoint`. `useAddPin` holds one state for the add flow: closed, the click popup at a point, or the panel with an optional point. It returns the click popup and an `onEmptyClick` handler beside `action` and `panel`. On a phone it returns nothing, so a tap opens nothing (NFR-05). `MapShell` gets an `onEmptyClick` prop and a `click` prop shaped like `pin`, and draws one floating popup at a time. `PinForm` takes `point` and writes it into the coordinates field with `pointText`, latitude first, 6 decimals. A new `point` while the panel is open replaces only that field.

## Decisions

**D6 · Where the coordinates field gets its text** · Decides: Tech lead

`pointText` in `ClickPopup.tsx` writes "latitude, longitude" with 6 decimals. It is private. The plan of #1187 says "#868 exports it for the coordinates field". `ClickPopup` is in `CONTROLS`, so a change to its file is a [design system input](../design/CANVAS.md#changing-the-design-system). #868 names no design system step and has no Constraint.

- **A.** `ClickPopup.tsx` exports `pointText`. `ClickPoint` moves to `app/components/overlays/types.ts`. `PinForm` and `MapView` import both. The build runs step 2. A local session that the tech lead starts runs steps 3 to 5. No board shows the change, so step 6 applies. Cost: one local session, and the PR stays a draft until it runs.
- **B.** `PinForm` writes the text with its own `toFixed(6)`. Cost: a second copy of the format, which `docs/code-rules.md` bars. The popup and the field can drift apart.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D7 · The proof that a save puts the Pin on the clicked point** · Decides: Tech lead

The save test of `e2e/pin-form.spec.ts` adds one Pin to the seeded Tree. `e2e/pins.spec.ts` allows 9,995 or 9,996 Pins in its counts. The seed leaves room for five more Pins.

- **A.** A second e2e save in `e2e/map-click.spec.ts`: click, "Add a pin here", fill the other fields, save. Then the test reads the new Pin under the clicked pixel. `ALL` in `e2e/pins.spec.ts` allows 9,995 to 9,997. Cost: about 40 lines, and one more Pin in the seeded Tree in each run.
- **B.** Vitest only: the `useAddPin` test proves that the save input holds the clicked point. Cost: no test proves the whole path on `/`.
- **Other:** your own.

**Answer: A** (@henetiriki)

## Alternatives considered

- The click state in `MapWithPins`, beside the open Pin: the add flow would then split over two files. `PinFormScreen` would also lose the state that it gets from `useAddPin`.
- Remount `PinForm` with a `key` on each click: the Person, date and other fields would clear. The Spec changes only the coordinates.
- A second follow hook in `MapView` for the click: the Pin popup and the click popup never show together, so one followed point is enough.

2. Do the same for `MapShell`, then `PinForm` (D6), then `useAddPin`, then `MapWithPins`. Commit each with its test.

## Risks

- A double click zooms the map and also opens the popup at the first click. The popup follows its point, so it stays correct.
- The coordinates field becomes controlled. The `fillPinForm` state of `e2e/design-states.ts` types into it, so the `pin-form*` design checks prove that typing still works.
- A click on empty map while the panel is open replaces typed coordinates with no warning. The Spec asks for this.

## Deviations

- `e2e/types.ts` gains `unproject`, which `map-click.spec.ts` calls.
- `MapWithPins.tsx` gets a `pinProp` helper for the line cap of a function.
- The build ran only `map-click.spec.ts`. The seed that `pins.spec.ts` needs was absent, so its three new tests are unproven until CI runs them.
- `MapWithPins.test.tsx` has no test of an empty click that closes the Pin popup. `MapShell.test.tsx` proves that the empty click calls both handlers, and `e2e/pins.spec.ts` proves the whole path.
- `MapWithPins.test.tsx` has no test of a Pin click with the panel open. `useAddPin.test.tsx` proves that the point stays.
- `features/map/types.ts` holds `ClickProp`, which `MapShell.tsx` and `useAddPin.tsx` use, so the click popup shape sits in one place.
- `e2e/map-points.ts` also holds `clickPopup`, `coordinates` and `afterPaint`, which both specs use.
- `useAddPin.tsx` drops its flow on a phone width, so a later desktop width starts closed. The tech lead chose to build this unlikely case after the review named it.
