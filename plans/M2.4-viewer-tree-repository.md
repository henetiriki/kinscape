# Plan: M2.4: Viewer and Tree-scoped repository

- **Spec:** #529
- **Requirement IDs:** [NFR-09](../docs/requirements.md#nfr-09), [NFR-10](../docs/requirements.md#nfr-10)
- **Status:** approved

## Approach

`lib/domain` gains `Result<T, E>` with `ok` and `err`, the `Viewer` (an Account id, or none) and the `TreeStore` port. Every store read takes an Account id and joins `tree_account`, so no unchecked read exists to skip to. `openTree(viewer, treeId, store)` in `server/trees/` returns `err('not-found')` for no Account, a malformed id (Postgres would throw on a bad uuid), a missing Tree or another Account's Tree; otherwise a `TreeRepository` that holds the id, which entity Specs extend. `treeAction` in `server/action.mts` takes a schema and a body, and returns a function of a Viewer, a tree id and raw input: open the Tree, parse the input (`err('invalid')`), run the body. One contract suite runs on the memory and PGlite stores.

## Decisions

**D1 · Which URL `account:add` uses** · Decides: Tech lead

The Spec says "only the database URL"; `main` has two.

- **A.** `KINSCAPE_DATABASE_DIRECT_URL`, from `.env.local`, like `db:migrate`.
- **B.** `KINSCAPE_DATABASE_URL`, the app's transaction pooler.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D2 · The Account's issuer** · Decides: Tech lead

`account` needs an issuer beside the subject (the Supabase user id).

- **A.** A constant, `supabase`, exported from `server/trees/` for M2.5's session adapter to match.
- **B.** The token's `iss`, `<KINSCAPE_SUPABASE_URL>/auth/v1`. The script then needs a second variable, which changes the Spec.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D3 · Finding an Account's Tree** · Decides: Tech lead

Sign-in must find the Account by identity and its Tree.

- **A.** M2.5 adds both lookups to `TreeStore` and the contract suite.
- **B.** M2.4 adds them now, with no caller yet.
- **Other:** your own.

**Answer: A** (@henetiriki)

## Risks

- **Size.** About 600 changed lines; past the cap, I stop and ask to split (rule 7).
- **Uuid errors.** `openTree` checks the id's shape before any query, so a bad id is `not-found`, never a thrown Postgres error.
