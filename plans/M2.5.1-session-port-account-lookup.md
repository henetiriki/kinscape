# Plan: M2.5.1: Session port and Account lookup

- **Spec:** #530
- **Requirement IDs:** [NFR-03](../docs/requirements.md#nfr-03)
- **Status:** approved

## Approach

`TreeStore` gains `findAccount(issuer, subject)` and `findTrees(accountId)`, which joins `tree_account` and returns `[]` for an Account with no Tree. `memoryStore(seed)` takes synthetic Accounts, some with no Tree. A `SignInPort` turns an email and password into a Supabase subject, or nothing. `signIn` asks the port, then `findAccount(ISSUER, subject)`, and returns `err('refused')` in every failed case. `parseEnv` reads `KINSCAPE_SUPABASE_URL`, `KINSCAPE_SUPABASE_PUBLISHABLE_KEY` and the test-only `KINSCAPE_MEMORY_ADAPTERS=1`. With it, `parseEnv` throws if `VERCEL` or `VERCEL_ENV` is defined, even empty, and needs no database or Supabase variable. `appAdapters()` picks the memory port and store together, seeded with one synthetic Account and Tree, or Supabase and `databaseStore(db())`.

## Risks

- **Bypass.** The memory port signs in a known synthetic user. Only `appAdapters()` builds it, through `parseEnv`, so D7's guard runs there and in `instrumentation.ts`. Tests cover both and empty values.
- **Vercel setting.** D7's guard needs "Enable access to System Environment Variables" on ([docs](https://vercel.com/docs/environment-variables/system-environment-variables)). It is on for `kinscape`; `docs/repo-settings.md` records it.
- **Leaks.** Tests spy on `console` and check that errors contain neither the password nor the email.
- **Size.** About 550 changed lines; past 600, I stop (rule 7).
