# Plan: M2.5.1: Session port and Account lookup

- **Spec:** #530
- **Requirement IDs:** [NFR-03](../docs/requirements.md#nfr-03)
- **Status:** approved

## Approach

`TreeStore` gains `findAccount(issuer, subject)` and `findTrees(accountId)`, which joins `tree_account` and returns `[]` for an Account with no Tree. `memoryStore(seed)` takes synthetic Accounts, some with no Tree. A `SessionPort` turns an email and password into a Supabase subject, or nothing. `signIn` asks the port, then `findAccount(ISSUER, subject)`, and returns `err('refused')` in every failed case. `parseEnv` reads `KINSCAPE_SUPABASE_URL` and `KINSCAPE_SUPABASE_PUBLISHABLE_KEY` (as named in `docs/repo-settings.md`) and the test-only `KINSCAPE_MEMORY_ADAPTERS=1`. With it, `parseEnv` throws if `VERCEL` or `VERCEL_ENV` is defined, even empty, and needs no database or Supabase variable. `appAdapters()` picks the memory port and store together, seeded with one synthetic Account and Tree, or Supabase and `databaseStore(db())`.

## Decisions

**D1 · What an Auth outage returns** · Decides: Tech lead

Supabase answers 400 for wrong credentials. A timeout, 429, 5xx or malformed body is something else.

- **A.** These throw an error that names only the status or "timed out". M2.5.3 shows "try again", not "wrong password".
- **B.** These return the same refusal as wrong credentials.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D2 · How e2e starts once Supabase variables are required** · Decides: Tech lead

`playwright.config.ts` sets only a dummy database URL, so the server would fail at start.

- **A.** It sets `KINSCAPE_MEMORY_ADAPTERS: '1'` and drops the dummy URL. This runs D7's guard in the production build now.
- **B.** It adds dummy Supabase values beside the dummy URL. M2.5.3 sets the test-only variable.
- **Other:** your own.

**Answer: A** (@henetiriki)

## Risks

- **Bypass.** The memory port signs in a known synthetic user. Only `appAdapters()` builds it, and it calls `parseEnv`, so D7's guard runs there as well as in `instrumentation.ts`. Tests cover `VERCEL`, `VERCEL_ENV` and empty values.
- **Leaks.** Tests spy on `console` and check that thrown errors contain neither the password nor the email.
- **Local dev.** `npm run dev` needs the Supabase variables in `.env.local`, or the test-only variable.
- **Size.** About 550 changed lines; past 600, I stop (rule 7).
