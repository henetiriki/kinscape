# Plan: M2.5.3.3: Sign-in page

- **Spec:** #565
- **Requirement IDs:** [NFR-03](../docs/requirements.md#nfr-03)
- **Status:** draft

## Approach

`server/auth/attempt.mts` runs a sign-in over the adapters and an injected clock: parse the input (Zod, trimmed and length-capped), refuse what `mayTry` refuses, `signIn`, count a failure (D1), `startSession`. A thrown error is `unavailable`. The server action `app/sign-in/actions.ts` sets `sessionCookie` and redirects to `safeReturnTo(returnTo)` (`lib/domain/auth/`): a path with one leading `/` that stays on this origin, else `/`. `app/sign-in/page.tsx` sends a valid session (`resumeSession`) to `/`. `SignInForm` keeps its fields controlled, so React's form reset keeps the email; on `refused` it clears the password and marks both fields, as `sign-in-phone-error` draws.

## Decisions

**D1 · When a failure is counted** · Decides: Tech lead

Parallel guesses all pass `mayTry` before any failure is counted (M2.5.3.2 plan › Risks).

- **A.** Before Supabase: count, verify, then remove that row on success or an outage. `ThrottleStore` gains `remove(emailKey, failedAt)` (about 50 lines). A burst is caught after a database round trip.
- **B.** After a refusal only. A whole burst reaches Supabase.
- **Other:** your own.

Recommended: A, because the throttle exists to stop guessing, and B lets each burst through.

**D2 · Where `/sign-in` joins `design:check`** · Decides: Tech lead

#553 lists it; until then `/match-design` can't run here.

- **A.** Here: `design/screens.json` lists `sign-in-desktop`, `sign-in-phone` and `sign-in-phone-error`, with states in `e2e/design-states.ts` that fill the fields. The `-unavailable` screens wait: the memory adapters can't fail.
- **B.** In M2.5.3.4, as #553 says. Here the page is compared with the JPGs by eye.
- **Other:** your own.

Recommended: A, because a mismatch is cheapest to fix in the PR that builds the page.

## Risks

- **Memory store across bundles** (M2.5.2 plan). If e2e shows the page missing the action's session, `appAdapters()` keeps its instance on `globalThis` (a deviation).
- **Locking the synthetic Account.** Failing e2e sign-ins use `researcher@example.com`, which has no Account, as the snapshots do.
- **`__Host-` cookie on `http://localhost`.** Chromium treats localhost as secure; e2e proves it.
- **Desktop wrong-details isn't drawn.** It places the phone board's Alert and field marks where `sign-in-unavailable` puts its Alert.
- **Size.** About 600 changed lines with D1: A; past that, I stop (rule 7).
