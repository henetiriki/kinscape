# Plan: M2.5.4.3: Account menu screens for M2

- **Spec:** #571
- **Requirement IDs:** [NFR-03](../docs/requirements.md#nfr-03)
- **Status:** draft

## Approach

The `account` variant of `Map.dc.html` and `Map-phone-states.dc.html` becomes the M2 menu: the "Export all data" row and the "Last backup" line go. The `export.json` entries `map-account-menu` and `map-account-menu-phone` keep their names (Spec D1 A). A new variant keeps today's menu for the two `-proposed` entries. The Screens table moves the two `-proposed` rows to "Proposed screens"; `screenNames` reads both tables, so no tooling changes.

## Decisions

**D1 · How the proposed boards are drawn** · Decides: Tech lead

Both menus are a variant of a full map board, not a board of their own.

- **A.** Add an `account-proposed` variant to `Map.dc.html` and `Map-phone-states.dc.html`; the two new `export.json` entries use it.
- **B.** Copy each board into a new `-proposed` file.
- **Other:** your own.

Recommended: A. A copy duplicates the map board and drifts.

**D2 · Which row the M2 board highlights** · Decides: Tech lead

Today's boards show "Export all data" in the hover colour. On open, the built `Menu` focuses the first item, which in M2 is Sources and attributions.

- **A.** Highlight Sources and attributions, so `design:check` in M2.5.4.4 matches the menu as it opens.
- **B.** Highlight no row.
- **Other:** your own.

Recommended: A.

**D3 · The Account menu row in DESIGN.md › States** · Decides: Tech lead

The row lists Export and the last backup time, which the M2 boards leave out.

- **A.** Add "(Export and the last backup time: M3)" to the row.
- **B.** Leave the row: it describes the proposed design.
- **Other:** your own.

Recommended: A. M2.5.4.4 builds from this file and must not add Export.

## Order of work

1. Record D1 to D3, then commit `plan(M2.5.4.3): approved by @<tech-lead>`.
2. Ask the tech lead in the PR to draw the boards on the canvas, run the refresh steps on this branch, and add the two `export.json` entries.
3. Read each changed board and check it against the Spec's Behaviour. List any mismatch in the PR for the tech lead.
4. Edit `DESIGN.md` and the three tests. Push, then run `gh workflow run design-agent-shots.yml --ref <branch>`, or ask the tech lead if that is denied.
5. Pull the shots commit. Run lint, `typecheck`, `format:check`, `words`, the tests, `validate:boundaries`, `e2e` and `design:export` ("No snapshot changed"). Paste the output.

## Risks

- **Red until the shots commit:** the export test and `e2e` fail between steps 2 and 5. Nothing is marked ready before then.
- **Board drift:** a canvas edit can move other parts of the map board. After the shots commit, compare each JPG with `main`'s; stop on any change outside the menu.
