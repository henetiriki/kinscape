## Approach

The design agent replaces the hand-drawn card in the `account` variant of `Map.dc.html` and `Map-phone-states.dc.html` with `KinScape.MenuPanel` (Spec D1 B). A positioned `<div>` holds the card where the hand-drawn card is now: 8 below the Avatar on desktop, under the pill on a phone. The board script gives `groups`: `[[{ icon: 'document', id: 'sources', label: 'Sources and attributions' }], [{ icon: 'signOut', id: 'sign-out', label: 'Sign out' }]]`, with `hovered: 'sources'` and no `footer`. The boards mount no `Divider`: the `<hr>` rules of `MenuPanel` are the dividers (Spec D2 A). The card gets a rule under the email that the hand-drawn card lacks. The `chrome` flag stays, and the design agent confirms it on both boards. No code, test or `export.json` entry changes.

## Order of work

1. Record D1. Commit `plan(M2.5.4.3.1): approved by @<tech-lead>`.
2. Ask the tech lead in the PR to do these steps in a signed-in local session on this branch:
   - Run the design agent with the [board swap prompt](../design/COMPONENTS.md#board-swap-prompt). Name the `account` variant of the two boards, `MenuPanel` and D1.
   - Run the [refresh steps](../design/CANVAS.md#refreshing-the-copy). Commit `design/canvas/` alone. Push.
3. Read each changed board. Check it against the Spec's Behaviour. List each mismatch in the PR for the tech lead.
4. Run `gh workflow run design-agent-shots.yml --ref spec/M2.5.4.3.1-account-menu-boards`. If GitHub denies it, ask the tech lead.
5. Pull the shots commit. Run all checks and `design:export` ("No snapshot changed"). Paste the output.

## Risks

- **Red until the shots commit:** `e2e` fails between steps 2 and 5. Do not mark the PR ready before then.
- **Board drift:** a canvas edit can move other parts of a board. After the shots commit, the diff must touch only the two M2 snapshots and their JPGs. Stop on any other change.
- **Export failure:** if the export rejects `MenuPanel`, keep the old board and raise a Bug that names the error.
