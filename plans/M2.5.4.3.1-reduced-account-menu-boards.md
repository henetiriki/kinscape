# Plan: M2.5.4.3.1: Reduced account menu boards

- **Spec:** #684
- **Requirement IDs:** [NFR-03](../docs/requirements.md#nfr-03)
- **Status:** draft

## Approach

The tech lead redraws the `account` variant of `Map.dc.html` and `Map-phone-states.dc.html` with only the parts that M2.5.4.4 (#572) builds (D1). The `account-proposed` variant does not change. The desktop board draws the map art, the Avatar and the open menu. It draws no brand and search bar, because the Spec lists only the map area and the Avatar, and the #572 route fills only the `account` slot. The phone board draws the map art, the search pill and the open card. It draws no Layers button and no date sheet, which is the phone form of the date dock. The map art keeps `role="img"`, so `design:check` hides it. The snapshot names, the sizes, `DESIGN.md` and the tests do not change.

## Decisions

**D1 · Where the reduced boards are drawn** · Decides: Tech lead

The panel, zoom buttons, dock and credits on desktop, and the Layers button and date sheet on a phone, show in every variant of the two map boards today.

- **A.** Add a flag to each map board. The flag hides those parts for the `account` variant only. `export.json` does not change.
- **B.** Draw two new boards, `Account-menu.dc.html` and `Account-menu-phone.dc.html`, as `add-pin` does. Point the two `export.json` entries to them, and remove the `account` variant from the map boards.
- **Other:** your own.

Recommended: A, because the map art stays in one file per form. The Render snapshots workflow commits each snapshot that changes, so a slip in another variant shows in the PR diff.

## Order of work

1. Record D1, then commit `plan(M2.5.4.3.1): approved by @<tech-lead>`.
2. Ask the tech lead in the PR to do these steps:
   - Draw the boards on the canvas.
   - Run the refresh steps on this branch.
3. Read each changed board and check it against the Spec's Behaviour. List each mismatch in the PR for the tech lead.
4. Push, then run `gh workflow run design-agent-shots.yml --ref <branch>`. If GitHub denies it, ask the tech lead.
5. Pull the shots commit. Run all checks and `design:export` ("No snapshot changed"). Paste the output.

## Risks

- **Red until the shots commit:** the `e2e` export check fails between steps 2 and 5. Do not mark the PR ready before then.
- **Board drift:** a canvas edit can move other variants. Only the two M2 snapshots and their JPGs may change in the shots commit. Stop on any other file.
