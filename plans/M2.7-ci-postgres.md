# Plan: M2.7: CI Postgres

- **Spec:** #532
- **Requirement IDs:** [NFR-09](../docs/requirements.md#nfr-09)
- **Status:** approved

## Approach

`scripts/ci-postgres.sh` makes a self-signed certificate (SAN `localhost`) in `/tmp/ci-postgres/`. It starts `postgres:17@sha256:…` on `127.0.0.1:5432` with a throwaway password and `ssl=on`, and waits for `pg_isready`. The `test` job runs it before `npm test`. A new helper, `contractDbs()`, gives each contract suite PGlite and, when `KINSCAPE_TEST_DATABASE_URL` is set, its own database on the container, so parallel files do not reset each other's schema. The `e2e` job runs the script, `npm run db:migrate` and `scripts/seed-ci.mts`, then `npm run e2e` with `KINSCAPE_MEMORY_SIGN_IN=1`. `SYNTHETIC` moves to `server/auth/synthetic.mts`, without `server-only`, so plain Node can import it.

## Decisions

**D1 · How the code finds the CA file** · Decides: Tech lead

- **A.** A new `parseCaFile(source)` in `server/env.mts` returns the path and refuses `KINSCAPE_DATABASE_CA_FILE` on Vercel. `parseEnv` calls it, and `rootCa()` passes `process.env`. The code rule on `process.env` names `parseCaFile` too.
- **B.** `parseEnv` and `parseDirectUrl` return the path, and `createPgDb` takes it as an argument. Four callers change.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D2 · How Playwright picks the mode** · Decides: Tech lead

- **A.** `playwright.config.ts` reads `KINSCAPE_MEMORY_SIGN_IN` from the job. If it is `1`, both servers get it, with `KINSCAPE_MEMORY_ADAPTERS` empty. Otherwise they get `KINSCAPE_MEMORY_ADAPTERS=1`. The `server/env.mts` rule covers the app, not test config.
- **B.** The config switches on `E2E_SPLIT`, which only the `e2e` job sets.

## Risks

- **Key file owner.** Postgres refuses a key that the runner's user owns. The script copies the key into the container and sets its owner there.
- **Default-CA test.** The `test` job sets `KINSCAPE_DATABASE_CA_FILE`, so `database.test.ts` stubs it empty for that test.
- **Digest pin.** Dependabot does not read shell scripts, so a person moves the pin.
- **CI time.** On a cache miss, `e2e` installs Chromium.

## Out of scope

## Deviations

- `scripts/ci-postgres.sh` takes `test` or `e2e`. It writes the variables for that job to `$GITHUB_ENV`, so the workflow holds no URL or password.
- The `e2e` job installs the browser with `--with-deps`, as it no longer runs in the Playwright image.
- The three contract files also run their hash and cascade tests on both backends. `server/db/__tests__/postgres.test.ts` tests `contractDbs()`.
- `SYNTHETIC` gains `treeName`, which the adapters and the seed share.
- `docs/code-rules.md` also lets test code (`__tests__/`, `playwright.config.ts`) read test-only variables.
- `parseEnv` checks the two memory flags on Vercel before the CA file. The CI `test` job sets the CA file for every test.
- `rootCa()` reads the CA path with a `turbopackIgnore` comment, so the build does not trace the whole project.
- The `e2e` job keeps the draft gate that `needs: image` gave it. `ci.yml` moves the pin instructions to the `design` job.
- The Playwright cache test also compares the `ci.yml` copy of the key and path.
- `e2e/dev-pages.spec.mts`: a comment said the two servers keep separate sessions. They may share the `session` table.
