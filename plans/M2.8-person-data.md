# Plan: M2.8: Person data

- **Spec:** #533
- **Requirement IDs:** [PPL-01](../docs/requirements.md#ppl-01), [NFR-09](../docs/requirements.md#nfr-09), [NFR-10](../docs/requirements.md#nfr-10)
- **Status:** approved

## Approach

Migration `0004_persons.sql` adds a `person` table from `server/db/TEMPLATE.sql`, with six `birth_` and six `death_` FuzzyDate columns. Sex is stored as the GEDCOM 7 code `M`, `F`, `X` or `U`, default `U`. A branded `PersonId` joins `lib/domain/ids/`. `lib/domain/persons/` holds the types, `personInputSchema` (dates as GEDCOM text through `parseFuzzyDate`) and `isLiving`. `TreeRepository` gains a `persons` group (`list`, `get`, `create`, `update`). The group takes the Tree id from the opened Tree and maps each row through `personView`, which adds `living`. Create uses the client's UUIDv7 and ignores a repeat. Update takes the version that the client read, and a stale version gives `conflict`. M2.9 (#534) wires the group and the schema to a server action.

## Decisions

**D1 · Where the Person methods go** · Decides: Tech lead

- **A.** On `TreeStore`: `listPersons`, `findPerson`, `addPerson`, `updatePerson`. The scoping test then guards them with no change. The _Tree data_ row in `architecture.md` changes "an entity's port" to "an entity's `TreeStore` methods".
- **B.** A separate `PersonStore` port with its own adapters, as that row says now. `TreeDeps`, `appAdapters` and `treeMethods` in `scripts/safety.mts` each gain it.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D2 · Size of the list** · Decides: Tech lead

The [code rules](../docs/code-rules.md#scale) forbid a response that grows with the Tree with no cap.

- **A.** `list` returns at most 2,000 Persons (the NFR sizing), by surname, given names, then id.
- **B.** Keyset pages of 200.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D3 · Field rules** · Decides: Tech lead

- **A.** No field is required. Each name has 200 characters or fewer, there are 20 variants or fewer, and notes have 10,000 characters or fewer. The schema trims text.
- **B.** As A, but a surname or given names is required.
- **Other:** your own.

**Answer: A** (@henetiriki)

## Alternatives considered

- A `living` column: it can go stale. The Spec says that the server derives it.
- Read a FuzzyDate back by parsing GEDCOM text: an extra round trip. `fuzzyDateOf` builds it from the stored parts.
