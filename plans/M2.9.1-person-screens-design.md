## Order of work

1. Record D1. Commit the approval.
2. The tech lead pastes the Spec's prompt on the canvas, runs the refresh steps and commits `design/canvas/` alone.
3. Check each new board against the Spec. List each mismatch in the PR.
4. Add the `export.json` entries, the `DESIGN.md` rows and the test count.
5. Add the icon and tests (D2). Run steps 2 to 9. The design agent swaps `People-list` (empty state), the two `account-people` variants and the Foundations pair.
6. Push. Run `gh workflow run design-agent-shots.yml --ref spec/M2.9.1-person-screens-design`. If GitHub denies it, ask the tech lead.
7. Pull the shots commit. Run all checks. Paste the output.
8. In the PR body, list the boards, the entry point and each hand-drawn part with its states.

## Risks

- **Board drift:** if the shots commit changes an existing snapshot, stop.
- **Colour check:** the export refuses a colour that is not a token. Ask the design agent to fix the board.
- **Required names:** `personInputSchema` requires no field (M2.8 D3 A). Spec D4 requires both names. M2.9.2 decides where that rule goes.

- `design/DESIGN.md` passed its 3,000-word budget with the 13 Screens rows: see D3.
