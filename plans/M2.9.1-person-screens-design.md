## Order of work

1. Record D1. Commit the approval.
2. Ask the tech lead in the PR to do these steps in a signed-in session:
   - Paste the Spec's prompt into a Claude chat on the canvas.
   - Run the refresh steps on this branch. Commit `design/canvas/` alone. Push.
3. Check each new board against the Spec. List each mismatch in the PR.
4. Add the `export.json` entries, the `DESIGN.md` rows and the test count in one commit.
5. If D1 is A, run `npm run design-system`. Paste its output.
6. Push. Run `gh workflow run design-agent-shots.yml --ref spec/M2.9.1-person-screens-design`. If GitHub denies it, ask the tech lead.
7. Pull the shots commit. Run all checks. Paste the output.
8. In the PR body, list the boards, the entry point and each hand-drawn part with its states.

## Risks

- **Red until the shots commit:** the export test fails between steps 4 and 7. Keep the PR a draft.
- **Board drift:** a canvas edit can change a built board. If the shots commit changes an existing snapshot, stop.
- **Colour check:** the export refuses a colour that is not a token. Ask the design agent to fix the board.
- **Required names:** `personInputSchema` requires no field (M2.8 D3 A). Spec D4 marks both names required. M2.9.2 decides where that rule goes.

- `lib/design/__tests__/design.test.ts` counts the snapshots (59 to 72). `lib/design/__tests__/screens.test.ts` lists the 13 new screens in `NOT_BUILT` until M2.9.2 adds their `screens.json` entries.
- `lib/design/shots.mts` renders `fuzzy-date-readings` full page. The board is 1,240 tall and the JPG cut it at 900.
- `design/DESIGN.md` passed its 3,000-word budget with the 13 Screens rows. The tech lead raised it to 4,000 in `scripts/word-count.mts` and `scripts/__tests__/word-count.test.ts`.
