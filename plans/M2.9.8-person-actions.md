# Plan: M2.9.8: Person actions: create and update

- **Spec:** #800
- **Requirement IDs:** [PPL-01](../docs/requirements.md#ppl-01), [PIN-04](../docs/requirements.md#pin-04), [NFR-09](../docs/requirements.md#nfr-09)
- **Status:** draft

## Approach

`app/people/actions.ts` (`'use server'`) holds `createPersonAction` and `updatePersonAction`. Each runs through `treeAction`, so the Tree comes from the cookie. `treeAction` gives only `invalid` for a schema failure, so the create action passes `z.unknown()`. The update action passes `{ person: z.unknown(), version }`, with `version` a positive integer. The body then calls `checkPerson` before it uses the input. `checkPerson` (`lib/domain/persons/form.mts`) parses with `personFormSchema`: `personInputSchema` with required given names and surname. It returns a `PersonInput`, or `{ fields }` with these error kinds:

- `givenNames`, `surname`: `required`.
- `variants`: `too-many`.
- `birth`, `death`: the `FuzzyDateError` of `parseFuzzyDate`.

On success the body calls `tree.persons.create` or `update`, which give the repeat, `conflict` and `not-found` results. An error holds kinds only, never input text. M2.9.9 (#802) wires the actions to the form.

## Decisions

**D1 · An input that the form already stops** · Decides: Tech lead

The Spec names errors for five fields. The form caps a name or spelling at 200 and notes at 10,000 characters. Only a client that is not the form sends a bad id, sex, version or a NUL character.

- **A.** Each of these gives `invalid` for the whole input, as `treeAction` does now. Nothing is saved.
- **B.** Each gives an error for its own field. The form needs a message for each.
- **Other:** your own.

Recommended: A, because the form cannot send these inputs, so it needs no message for them.

## Alternatives considered

- Give `treeAction` a function that turns Zod issues into field errors. It changes a shared API for one caller.
- Put the name rule in `personInputSchema`. The Spec keeps M2.8's schema free of required fields.

## Risks

- **The header.** A server action cannot set a response header. It answers on its page's route. M2.9.9 sets `Cache-Control: private, no-store` on `/people/new` and `/people/{id}`, and its check reads the header.
- **A thrown store error.** In production, Next replaces the message of a thrown action error with a digest. The actions log nothing.
- **Export shape.** Each export of a `'use server'` file must be an async function. `treeAction` returns one, and `npm run build` checks it.
