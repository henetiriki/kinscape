# Plan: SC.13.1: Screens hold at 200% text, and shared sizes get names

- **Spec:** #1211
- **Requirement IDs:** [NFR-05](../docs/requirements.md#nfr-05), [NFR-06](../docs/requirements.md#nfr-06)
- **Status:** approved

## Approach

The 200% check skips 390px for a set of desktop-only states (D2). Two layout fixes then clear the five other entries, so `lib/design/large-text.json` becomes `[]` (D3). Each SC.2 entry outside _Stays_ moves to a token, a `calc()` of tokens or a local value, by the kind table (D4 to D14). `npm run tokens` writes the 20 new tokens to `app/tokens.css` and `design/tokens.generated.ts`. `lib/design/sizes.test.ts` and `literals.test.ts` prove that no literal is left, and `npm run sizes` rewrites the list. The design system steps and Design: Render snapshots then refresh the cards, the boards and the snapshots.

## Alternatives considered

- A `Set<keyof typeof states>` type for the desktop-only set: `states` is a `Record<string, …>`, so the type checks nothing. A Playwright test checks the names.
- A `NoticeCard` spacer element in the markup: a `::before` spacer changes no markup, so `NoticeCard.test.tsx` and its three React 18 cases stay as they are.

## Order of work

1. Add the tokens. Run `npm run tokens`.
2. Change each CSS module by the kind table, then `Panel` and its callers. Run `npm run sizes`.
3. Write the `PersonField` test, and see it fail on the open list. Fix `closeOnScroll`.
4. Change the `NoticeCard` actions.
5. Add `DESKTOP_ONLY` and the spec change. Set `lib/design/large-text.json` to `[]`. Run `npm run e2e -- e2e/large-text.spec.ts`.
6. Change `states.mts`, the tests and `tokens.md`.
7. Run the checks of AGENTS.md › Commands.
8. Add a `ProgressBar` line to the Behaviour of #1208 (D13).
9. Design system steps (_Issue text_ of [Changing the design system](../design/CANVAS.md#changing-the-design-system)):
   1. Step 2: run `npm run design-system`.
   2. Steps 3 to 5: a local Claude Code session that the tech lead starts runs them. The session needs a signed-in account.
   3. Step 7: the same session edits the four `Panel` boards, then runs Design: Render snapshots once.
   4. Run `npm run design:check`. If a board that draws a value of the kind table fails, that session edits the board (Constraints). The PR lists each board edit.

## Risks

- About 960 changed lines, over the cap of 660. The tech lead adds `size: accepted` (D1).
- A field compensation is now in rem, so it grows at 200% text. The `main` px values hold at the default text size only. The gallery test reads them there.
- A new token can equal a literal elsewhere. Only the converted rules hold 4px or 60px in a size property, so `literals.test.ts` stays green.
- A check can reject a `motion` duration that does not refer to `scale.duration`. If `design.test.ts` fails on it, the build reports it as a "Big:" line.
- The 22 desktop-only screens lose their 390px run. The 8 phone screens keep it.

## Deviations

- Big: `TextLink` `.anchor` keeps `1em` and `1px`. `TextLink.test.tsx` asserts that exact text and is not in Files that change. Its 2 entries stay in `off-token-sizes.json`, so the list holds 8 entries, not only _Stays_.
- A local session built the four `design/canvas/project/Map*.dc.html` board rows and ran design system steps 3 to 7 and Design: Render snapshots. That session has no browser, so it did not run `npm run design:check`. The CI `design` job runs it when the PR leaves the draft state.
- `lib/design/states.mts` reads `design/kinscape.tokens.json`, not `design/tokens.generated.ts`: lint bars a `.ts` import in a `.mts` file.
- `features/people/components/PersonForm.module.css`: `.dialogActions` wraps. The 32px `Dialog` padding left the "Leave without saving" button 23px too wide at 200% text.
- `design/topics/foundations.md`: a `motion` row for `autofill-hold`. `system.test.ts` requires one row for each motion token.
- `Panel.test.tsx` passes `gap='m'` in the second render, so the test shows a change from the default `'l'`.
