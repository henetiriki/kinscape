# Plan: SC.4: App and map code read a typed token module

- **Spec:** #1194
- **Requirement IDs:** None. Tooling and code only.
- **Status:** draft

## Approach

A new Style Dictionary format in `lib/design/style-dictionary.mts` writes `design/tokens.generated.ts`, beside `app/tokens.css` and `design/tokens.json`. The module has one `as const` named export for each token group, with the resolved value of each token in the shape of `design/tokens.json`. Thus, a removed or renamed key fails `npm run typecheck`. Each group is its own export, so the bundler drops a group that a client module does not import (Flagged concern). Lengths and durations that code needs as numbers come from a second export for each group (D5). The 13 readers then import only the groups that they use, and they drop `resolveTokens`.

## Decisions

**D5 · How a number reaches code** · Decides: Tech lead

`design/tokens.json` holds each length as text, such as `"56px"`. Acceptance check 1 compares the module with that text. `MapLayout.tsx` needs the map padding as numbers. `Toast.tsx` reads `motion.toast` (`"4000ms"`) with `Number.parseInt`, and the Summary says that no code reads a unit out of a string.

- **A.** Each group export holds the text value, as `design/tokens.json`. A second export for each group with a `px` length (`layoutPx`, `sizePx`, `typePx` and the others) holds each `px` length as a number. `motionMs` holds each duration as a number in ms. `Toast.tsx` reads `motionMs.toast`. Cost: about 200 more generated lines.
- **B.** As A, but only lengths get numbers. `Toast.tsx` keeps `Number.parseInt`. Cost: about 190 more generated lines.
- **C.** Each `px` length is a number in its group export, and no text form exists. Acceptance check 1 compares after the test adds `px`. `usePhone.ts` adds `px` to the breakpoints. Cost: Acceptance check 1 changes its meaning.
- **Other:** your own.

Recommended: A, because each reader then gets a number with no parse, and the text export still matches `design/tokens.json` exactly. B is a little smaller, but `Toast.tsx` still reads a unit out of a string.

**D6 · The architecture row names the old reader path** · Decides: Tech lead

The "Tokens are the one source" row of `docs/architecture.md` says that MapLibre paint values and map padding read `design/tokens.json`. After this Spec, that text is false. SC.4.2 (#1196) lists `docs/architecture.md` in its docs. The [pattern-table rule](../docs/code-rules/pattern-table.md) says that a new file goes in the _Where_ cell of its row.

- **A.** This Spec edits the row: the readers read `design/tokens.generated.ts`. _Where_ adds the module. _Enforced by_ adds the stale check of the module. #1196 keeps its other `docs/architecture.md` edits. Cost: one row.
- **B.** Leave the row. #1196 edits it. Cost: the row is false until #1196 merges.
- **Other:** your own.

Recommended: A, because the row then says what `main` does.

## Alternatives considered

- One default export of the whole tree: each client bundle then carries every group.
- A knip `@public` tag on each export: the knip `ignore` entry does the same in one line, as for `design/canvas/**`.

## Order of work

1. Write the failing format tests in `style-dictionary.test.ts`. Add the format and `OUTPUTS.ts`. Run `npm run tokens`.
2. Add the stale, resolved-value and `@ts-expect-error` tests in `design.test.ts`. Add the three ignore entries.
3. Move the 13 readers and their tests, one commit for each folder. Run `npm test` after each.
4. Edit `app/globals.css`, `design/topics/tokens.md` and `docs/architecture.md`.
5. Run the checks in `AGENTS.md` › Commands.
6. Run `npm run design-system` on `main` and on the branch. Put both sha256 lists and the `design-system.json` diff in the PR Evidence.
7. Push. Keep the PR a draft. Ask the tech lead in the PR to run steps 3 to 5 of [Changing the design system](../design/CANVAS.md#changing-the-design-system) in a local Claude Code session. The session needs a signed-in account.
8. After steps 3 to 5, run step 6. No board shows the change, so step 7 does not run.

The done checks: steps 2 to 6 are done on the branch. Every file under `canvas/project/ds/kinscape/` has the same sha256 as `.design-system/project/`.

## Risks

- **A key order or a value type differs from `design/tokens.json`.** The `map` numbers are numbers, and `z`, `tracking` and `weight` are text. The resolved-value test compares each group with `resolveTokens(design/tokens.json)` with `toStrictEqual`.
- **A client bundle keeps every group.** After `npm run build`, compare the total size of `.next/static/chunks/` with `main`. Put both sizes in the PR Evidence.
- **`bundle.js` differs in more than the tokens.** Step 6 compares the sha256 lists. Only `components/bundle.js` and `design-system.json` may differ.
- **The diff passes `CAP`.** About 950 lines with the module. The tech lead adds `size: accepted` (D4 of #1194).
