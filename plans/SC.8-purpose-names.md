# Plan: SC.8: Shared components use purpose names for spacing, and borders, timing and stacking get names

- **Spec:** #1200
- **Requirement IDs:** None. This Spec changes no behaviour.
- **Status:** approved

## Approach

The token file gets the purpose layer: `space.inset.*`, `space.gap.*` and `space.stack.*` point at `scale.space` steps. It also gets `border` widths, the motion easing and offsets, four `map` opacities and the new `z` values. The `space.N` tokens stay, with `$deprecated`. `groups.mts` gives opacity, border width and transform lengths a group, so one table drives both the size check and the literals test. Then each `.module.css` line changes to a name with the same computed value, and `npm run sizes` shortens the list. The design system shows the new `border` and `motion` families and leaves out the deprecated names. Its `tokens.css` keeps those names in their own block.

## Decisions

**D18 · The size names of the spacing purpose names** · Decides: Tech lead

The Spec lets the plan set the sizes. `inset` uses all 10 `scale.space` steps, `gap` uses 6 (7 with D19 A) and `stack` uses 2.

- **A.** One suffix per step, the same in each role: `2xs` (4px), `xs` (8), `s` (12), `m` (16), `l` (20), `xl` (24), `2xl` (32), `3xl` (40), `4xl` (48), `5xl` (64). `space-gap-m` and `space-inset-m` are the same step. A role has only the suffixes that it uses.
- **B.** Each role counts its own sizes: `space-gap-1` to `space-gap-7`. The same number can mean a different step in two roles.
- **C.** The step number: `space-inset-400`. A name repeats its scale step, so the size part adds no meaning.
- **Other:** your own.

**Answer: A** (@henetiriki)

**D19 · Which lines set the sizes** · Decides: Tech lead

#1201 (SC.9) moves the `features/` lines. Its Behaviour gives a line with no purpose name an `own:` reason.

- **A.** The sizes come from `app/components` and `features/`. This adds `space-gap-3xl` (40px), which only `PersonForm` `column-gap` uses. SC.9 then needs no `own:` reason for spacing. #1201 keeps its text.
- **B.** The sizes come from `app/components` only: 18 names. In SC.9, the `PersonForm` `column-gap` gets an `own:` reason.
- **Other:** your own.

**Answer: A** (@henetiriki)

## Alternatives considered

- A separate rule table for the new groups in `sizes.mts`. Rejected: `literals.mts` and `sizes.mts` share `RULES` in `groups.mts`, and one table keeps them in step.
- A `transition` token with a reference inside it. D9 rejects it.

## Order of work

1. Write the tool tests: `dtcg`, `literals`, `sizes`, `notes`, `system`. See each fail on the behaviour.
2. Change `dtcg.mts`, `groups.mts`, `sizes.mts`, `notes.mts`, `system.mts`, `types.ts` and `scripts/design-system.mts`.
3. Edit the token file. Run `npm run tokens`.
4. Edit the `.module.css` lines. Run `npm run sizes`.
5. Edit `tokens.md`, `foundations.md` and `word-count.mts`.
6. Step 2 of Changing the design system: run `npm run design-system`.
7. Run the checks in AGENTS.md › Commands, and `npm run design:check`.
8. Steps 3 to 5: the tech lead runs them, or a local Claude Code session that the tech lead starts. The session needs a signed-in account. The CI build asks for them in the PR and keeps the PR a draft.
9. Step 6: push the branch. No board shows the change, so step 7 does not run. If the `design` or `gallery` job fails on a snapshot, run the workflow Design: Render snapshots.

## Risks

- **`foundations.md` budget.** The three rows add about 15 words to a budget of 800. If `npm run words` fails, the build makes the Motion rows shorter.
- **`$deprecated` in Style Dictionary.** It can write a comment or a warning into `app/tokens.css`. `design.test.ts` fails on a stale file, and the build reads the diff of `app/tokens.css`.
- **New families in the design system.** The type reads `focus`, `layout` and `z`, so `border` and `motion` follow the same shape. Step 3 shows a family that the type rejects.
- **Stacking.** The order stays furniture, MapLibre corners (2), action bar, popup, menu. The new `design.test.ts` case and `npm run design:check` prove it.
