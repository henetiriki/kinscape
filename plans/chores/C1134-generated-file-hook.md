# Plan: C1134: Block edits to generated design files with a hook

- **Spec:** #1134
- **Status:** approved

## Approach

Each settings file gets a second `PreToolUse` entry with the matcher `Edit|Write`, after the Bash entry. Its command is one inline `jq -c` program, as the Bash hook is. The program does these steps:

1. It reads `.tool_input.file_path`.
2. It cuts the prefix `$CLAUDE_PROJECT_DIR/` or `$GITHUB_WORKSPACE/`, if the path has one.
3. It cuts a leading `.claude/worktrees/<name>/`. The path is now relative, so an absolute path gets the same result and the same reason as its relative path.
4. It tests the relative path against `^design/source/[^/]+\.html$`, `^design/[^/]+\.jpg$` and `^design/cards/[^/]+\.png$`. The CI hook also tests `^design/canvas/`.
5. On a match, it prints a `deny` with the step 5 reason of its file. `<path>` in the reason is the relative path. On no match, it prints nothing.

The local hook prints nothing when `$ENV.GITHUB_ACTIONS` is `"true"`. `kse-*.svg` and `fonts.css` match no pattern, so both hooks allow them.

A new `describe` in `agent-settings.test.ts` runs each hook through `bash -c`, as the Bash hook test does. The input is `{tool_name, tool_input: {file_path}}`. Each case sets `CLAUDE_PROJECT_DIR` and `GITHUB_WORKSPACE`, and clears `GITHUB_ACTIONS`. CI sets `GITHUB_ACTIONS=true` when it runs `npm test`. If a case does not clear it, the local hook allows each path.

## Decisions

**D2 · Who writes the local hook's tests** · Decides: Tech lead

The Constraints give the CI agent the `.github/agent/settings.json` row and its test, and the tech lead the `.claude/settings.json` row. They do not say who writes the local hook's tests. [`C1133`](C1133-spec-check-items.md) let the CI agent write a test that failed until the tech lead built the hand-back row.

- **A.** The CI agent writes the tests of both hooks in one table of sample paths. The local hook's cases fail until the tech lead adds the hook. The `hand-back` label keeps the PR a draft until then.
- **B.** The CI agent writes only the CI hook's tests. The tech lead writes the local hook's tests with the hook. `npm test` passes after each commit, but the local hook gets no failing test first.
- **Other:** your own.

## Alternatives considered

- Deny rules such as `Edit(design/source/*.html)`. Rejected: a deny rule gives no reason, so the agent does not learn the fix.
- One hook, in `.claude/settings.json`, with a CI branch. Rejected: CI reads that file from the PR's checkout, and `.github/agent/settings.json` from `main`.
- A test that reads `AGENTS.md` and `design/CANVAS.md` for the removed sentences. Rejected: a test that looks for missing text guards nothing later. A `git grep` in the Evidence proves the check.

## Risks

- Under D2 A, `npm test` fails on the PR from step 1 to step 5. The `hand-back` label keeps the PR a draft, so the failure does not reach `main`.
- The local hook loads in a CI run from the PR's checkout. After the merge, a CI session sees both hooks. The local hook prints nothing there, and the CI hook gives the reason.
- A path with `..` or a symlink in it passes both hooks. Likelihood: low; Claude Code sends the absolute path that it writes, and no shown session uses `..`. Fix cost: a path normaliser in each `jq` program. The plan builds no fix.
- A shell write (`cp`, `>`, `git checkout`) passes both hooks. The Chore puts Bash out of scope, and the `design` and `gallery` jobs still find the change.
