# Plan: C1181: Split the script, server and lib functions over 60 lines and remove their disables

- **Spec:** #1181
- **Requirement IDs:** None. This Chore changes no behaviour.
- **Status:** approved

## Approach

Each of the 22 functions gets Extract Function and Split Phase until each function holds 60 lines or fewer. Then its disable line goes. A Node function moves its phases to new module-level functions in the same file, with no `export`. The same tests then run the same lines, so coverage stays at 100%. A page function (one that Playwright sends to the page) cannot call a module-level function. `fillTemplate` gets two new page steps (D1). The three other page functions stay one step each (D2). At the end, `CAP` is 0.

## Decisions

**D2 · How to fit `pageHtml`, `defineBuilder` and `defineStyleHelpers`** · Decides: Tech lead

These three page functions in `scripts/design-export.mts` have about 65, 71 and 66 lines. D1 covers only `fillTemplate`. Constraint 2 and done check 3 allow new page steps and test lines only for `fillTemplate`. #1182 has no value for this.

- **A.** Keep one page step each. Move the inline casts and parameter types to local types at module level: the page source then holds no reference to them. Merge loops where the output stays the same, such as the `<link>` of `fonts.css` in one `Object.assign`. Cost: denser code. If a function cannot fit, the build stops and asks in the PR.
- **B.** Split `pageHtml` into page steps by phase, such as a new `resolveStyles` for `var()` and `calc()`. The other two take A. Cost: one or two new exported names, and 5 calls in the `pageHtml` tests and `e2e/design-export.spec.mts:88` change. The tech lead edits Constraint 2 and done check 3 of #1181 first.
- **Other:** your own.

**Answer: A** (@henetiriki)

## Alternatives considered

- **Module-level helpers for a page function.** The unit tests pass in jsdom, but the export fails in Chromium.
- **A fixed disable for a page function.** #1182 then cannot ban every disable.

## Order of work

1. Before any code change, run `npm run design-system`. Keep the sha256 of each file under `.design-system/project/` for the PR Evidence.
2. Refactor `scripts/design-export.mts` and its two test files in one commit. Run `npm test`, `npm run lint` and `npm run e2e -- e2e/design-export.spec.mts`. If Chromium does not start, the CI `e2e` job is the check.
3. Refactor the other `scripts/` files in one commit. Refactor `server/` and `lib/` in one commit. Run `npm test` and `npm run lint` after each.
4. If `main` has a different set of disables, refactor that set (Constraint 3). Set `CAP` to 0. Run `npm test`.
5. Run `npm run design-system` again. Compare each sha256 with step 1. Only `project/design-system.json` may differ.
6. Run the checks of `AGENTS.md` › Commands.

## Risks

- A page step that reads a module-level value fails only in Chromium. `npm run e2e -- e2e/design-export.spec.mts` runs the steps in Chromium.
- A helper of `parseEnv` can widen the inferred return type. `npm run typecheck` and the `server/env.mts` tests catch it.
- A helper of a store can change the order of the checks in a write. The contract tests in `server/trees/__tests__/contract.ts` run on both stores.
- Prettier can move a `v8 ignore` comment off its line. Read each diff for moved comments.
